## 职责与边界

负责：接收记录器上传并写成已完成任务和投入记录；告诉记录器哪些目录名已绑定；给会话开始时的简报提供数据；保存和返回「进行中的窗口」；页面里设置目录名、显示自动记录的东西。

不负责：怎么从钩子事件算出任务和分钟（记录器里做，见 [编程自动记录](编程自动记录.md)）；令牌管理（[登录与令牌](登录与令牌.md)）；改动怎么留底和撤销（[AI 改动记录](AI改动记录.md)）。

## 数据的变化

| 位置 | 变化 | 说明 |
| --- | --- | --- |
| `Project.dirNames?: string[]` | 新增，可选 | 目录名，最多 8 个，每个 1–60 字、去掉首尾空白、不含 `/` 和 `\`；整份数据里不分大小写不重复（同一个目录名只能绑一个副业） |
| `TimeEntry.minutes?: number` | 新增，可选 | 实际计入的分钟数（整数）。并行窗口平分后比 `end − start` 短；没有这一项按 `end − start` 算（手动计时和补记不变） |
| `RecordOrigin` | `"ai"` 之外加 `"coding"` | 自动记录的任务和投入记录带 `origin: "coding"` |
| `minutesOf(entry)` | 改一处 | 有 `minutes` 用 `max(0, round(minutes))`，没有按 `end − start`。所有统计、时薪、回顾、MCP 读工具都从这一个函数取分钟，不再另算 |
| D1 汇总查询 `sumEntryMinutesByTask` | 同步改 | SQL 里按同一规则取分钟 |
| 备份 / 导入 | 新字段原样带过 | 老备份没有这些字段照常能导入 |

自动记录的任务字段：状态「已完成」，`completedAt` 是到站时刻，`plannedFor`、`dueOn`、`startAt` 为空，`estimateMin` 为 0，`origin: "coding"`，`notes` 是提交清单（每行 `短哈希 提交说明`，最多 2000 字）。含有 `origin: "coding"` 的任务不计入「估时准不准」（`estimateAccuracy` 跳过）和当天计划容量。

## 目录名的设置

- 副业表单（新建和编辑）加「目录名」：输入后回车加成一个小标签，可删；输入框旁小字写「用来认出你在哪个文件夹写代码」。保存时校验长度、字符、重复；重复时提示「这个目录名已经绑给了『某某』」。
- 副业详情里，有目录名时在目标下面显示成小标签；没有就不显示这一块（不放空提示）。
- 用对话绑定：MCP 的 `manage_project` 新增 `directories`（整个替换）、`addDirectories`、`removeDirectories` 三个可选参数，规则同上，冲突时报英文错误并写明占用它的副业。`list_projects`、`get_project` 的输出加 `directories`。
- 词条进 `projects` 命名空间，中英文各一份。

## 接口（`worker/recorder/`）

四个接口都在 `/api/recorder/` 下，只认访问令牌、口令登录和 Access（和其他 `/api` 接口同一套身份校验）。写操作（上传、更新进行中）要求「直接改」档的令牌（口令和 Access 也行），其余档返回 403「记录器需要一个『直接改』权限的令牌」。

约定的类型在 `src/sync/recorder-protocol.ts`，记录器、Worker、页面共用。

### `GET /api/recorder/bindings`

返回当前所有已绑定的目录名：

```ts
interface BindingsResponse {
  bindings: { dir: string; projectId: string; projectName: string }[]   // dir 已转小写
}
```

任何档的令牌都能读。记录器每次同步前取一次，缓存在本机。

### `GET /api/recorder/briefing?dir=<目录名>`

给会话开始时往 AI 上下文里加的简报。读档就够。

```ts
interface BriefingResponse {
  bound: boolean                     // 目录名没有绑定副业时只返回 bound: false
  today: string                      // 用户时区的今天
  project?: { id: string; name: string; stage: ProjectStage }
  plannedToday: BriefingTask[]       // 这个副业今天计划的、没做完的，最多 10
  overdue: BriefingTask[]            // 逾期的，最多 5
  open: BriefingTask[]               // 没做完的其他任务，按优先级、截止日、编号排，最多 15
}
interface BriefingTask { code: string; title: string; status: TaskStatus; priority: Priority; estimateMin: number; plannedFor: string | null; dueOn: string | null }
```

只查这个副业的未完成任务，一次查询加副业和作息设置，CPU 很小。

### `POST /api/recorder/upload`

```ts
interface UploadRequest {
  client: { name: string; version: string; agent: "claude-code" | "codex" }
  tasks: UploadTask[]                // 最多 10 个
}
interface UploadTask {
  key: string                        // 稳定的键，重复上传不会重复记；≤ 200 字
  dir: string                        // 目录名
  title: string                      // 1–80 字
  source: "commit" | "done" | "idle" | "end"
  finishedAt: number                 // 到站时刻
  commits: { sha: string; subject: string }[]     // ≤ 20，subject ≤ 200 字
  taskSeq?: number                   // 提交说明里写了 T-123：把已有任务标成完成
  entries: UploadEntry[]             // ≤ 20；可以为空（没有计入时间的任务）
}
interface UploadEntry { key: string; start: number; end: number; minutes: number }   // minutes 整数 ≥ 1，start < end
interface UploadResponse {
  created: { tasks: number; entries: number }
  skipped: { key: string; reason: "unbound" | "duplicate" | "invalid" }[]
  changesetId: string | null
}
```

服务器的处理：

1. 校验形状和上限；一次请求算出的改动不超过 40 条（任务 + 时间段），超了返回 400，让记录器分批。
2. 读副业列表，按目录名（不分大小写）找副业；找不到的任务整个跳过，原因 `unbound`。
3. 任务编号和时间段编号都由 `key` 算出：`t-r` + `sha256(key)` 的前 14 位（base64url），时间段 `E-r` + 同样。已存在的任务不重复建（原因 `duplicate`），但它缺的时间段照建（零碎提交并进上一个任务的情形）。
4. 有 `taskSeq` 且找到对应任务：不新建，任务没完成就标成完成并记 `completedAt = finishedAt`，已完成的不改；时间段挂到该任务，时间段的副业取该任务的副业（没有就取目录名绑定的副业）。找不到就当普通任务新建。
5. 经改动记录服务写入：工具名 `recorder`，理由「编程自动记录」，批量模式（不触发预览和限速），写入后在 AI 动态里是一条「新建 N 个任务、M 段投入」，可以整批撤销。没有任何要写的改动时不建改动包。
6. 重复上传同一批：全部 `duplicate`，不产生改动包。

### `PUT /api/recorder/live`、`GET /api/recorder/live`

记录器把「正在进行的窗口」告诉服务器，页面轮询显示。

```ts
interface LiveWindow { session: string; dir: string; agent: "claude-code" | "codex"; since: number; minutes: number }
// PUT 请求体 { windows: LiveWindow[] }：整个替换，只保留已绑定目录的窗口，最多 20 个；存在 settings 表的 recorder_live 键里
// GET 返回 { windows: (LiveWindow & { projectId: string; projectName: string })[]; updatedAt: number }
```

- `since` 是这个窗口攒着的、还没到站的第一个计入段的开始；`minutes` 是攒到现在已经计入的分钟（平分后）。
- `updatedAt` 超过 5 分钟的当作过期：GET 返回空列表。记录器在每次钩子触发的同步里更新，窗口到站或结束后立刻再 PUT 一次（去掉它）。

## 改动记录服务：批量模式

`SubmitInput` 新增可选 `bulk?: boolean`（`worker/mcp/types.ts`），只给记录器上传用：

- 要求令牌是「直接改」档（页面登录的口令 / Access 身份也行）。
- 不触发预览阈值（`PREVIEW_THRESHOLD`）、不计入 10 分钟 200 条的限速。
- 单次上限改为 40 条改动（`MAX_BULK_CHANGES`），仍低于 D1 免费版单次请求 50 次查询的上限。
- 其余（冲突检查、原子状态转换、留底、撤销）完全不变。

## 页面

### 今天页「投入」列表（现有 `FocusCard`）

- 每一行：左边真实的起止时间，中间任务名（没有任务写副业名），右边副业色块和分钟数（`minutesOf`，并行时比起止之差短）。几行起止重叠就是并行。
- 自动记录的行，任务名前放一个 12px 灰色小图标（`SquareTerminal`），悬停提示「自动记录」/「Recorded automatically」。
- 总计用 `minutesOf` 求和，已经是平分后的，加上进行中窗口攒到现在的分钟。
- 进行中：列表最上方，每个窗口一行，样子和计时器那一行一致（黄色底色、`progress` 色），左边「HH:mm 起」，中间副业名，右边攒到现在的分钟。数据来自 `GET /api/recorder/live`，页面可见时每 30 秒刷新，窗口回到前台立即刷新；失败保留上一次的数据。只在在线版请求，没有进行中的窗口就不显示这一块。

### 时间线左边的「实际」轨道

- 今天页中栏的时间线，在时间刻度和任务块之间加一条 6px 宽的细轨道；今天每条投入记录画一根细条（高度按真实起止，颜色是副业的识别色），同一时段的几条并排（`layoutBlocks` 的算法），进行中的窗口画到现在，末端渐淡。
- 悬停一根细条显示任务名和分钟数；不可点击、不可拖动，不影响任务块的拖动和选择。
- 手机宽度（小于 768）不显示这条轨道。

### 其他地方

- 任务卡片、任务详情、收支无关：自动记录的任务在辅助行和详情标题前放同样的小图标（和「AI 记录」小图标并列，二者不会同时出现在一条记录上）。
- 任务看板和列表：自动记录的任务直接在「已完成」里，卡片上写用时（现有卡片已经显示累计投入）。
- 副业页、概览、回顾：都经 `minutesOf`，自动算平分后的时间。
- AI 动态：记录器的上传显示成一条改动包，客户端名取令牌名称（建议起名「记录器」），概括「新建 3 个任务、4 段投入」，沿用现有展示。
- 「连接 AI」弹窗：新建令牌后，客户端分段里多一个「记录器」，给出安装和配置命令（见 [编程记录接入](编程记录接入.md)）；选「记录器」用途时权限默认选「直接改」并在小字里说明原因。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 加一个 `minutes` 字段，不改起止时间 | 起止时间保持真实，几行重叠一眼看出并行；统计只认 `minutesOf`，改一个函数全局生效 |
| 任务和时间段的编号由客户端的键算出 | 重复上传、绑定后补传都不会重复记，不需要服务器记「收过哪些」 |
| 任务引用 `T-123` 不新建任务 | 提交说明里写了任务编号，说明这次提交完成的就是那个任务；时间记到它名下，统计才准 |
| 上传走改动记录服务 | 自动记的东西也能在 AI 动态里看到、整批撤销；和 AI 其他改动同一套留底 |
| 批量模式单次上限 40 条 | D1 免费版单次请求约 50 次查询，改动明细和状态更新要留余量 |
| 进行中的窗口放 settings 表，不进同步记录 | 它是瞬时状态，几分钟就过期，不该同步到每台设备、也不该留历史 |
| 不新增同步记录种类 | 同步引擎、备份、导入都按已知种类处理，加种类要动浏览器端合并规则，收益不大 |
| 自动记录的任务不填预估和计划日 | 不占当天计划容量，不污染「估时准不准」 |
