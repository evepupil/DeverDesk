# 存储层

- 模块定位：数据仓库和「数据存在哪」之间的一层。页面和数据仓库只管改数据，存到浏览器还是云端由这一层决定。
- 对应代码：`src/state/storage/`（`types.ts` 接口、`local.ts` 浏览器存储、`index.ts` 选用哪种存储），调用方是 `src/state/store.ts`
- 所属里程碑：[M1 本地版 / 在线版切换](../roadmap.md#m1)
- 当前状态：已完成（本地存储）；云端存储在 M2 接入
- 最近更新：2026-09-30

## 职责与边界

负责：启动时读出这台设备上保存的数据；每次修改后保存，并告诉数据仓库有没有存上。
不负责：数据怎么改（数据仓库的各个操作）、界面上的保存失败提示（外框的保存反馈）、样例数据生成。

## 结构与数据流

```
页面操作 → 数据仓库的操作（新建任务、记一笔……）
              │ 算出改之后的完整数据(next)
              ▼
        存储层 save(next) ──→ 返回这台设备上有没有存上
              │
              ├─ 本地存储：整份写进浏览器（键 deverdesk:data，格式版本 1）
              └─ 云端存储（M2）：和自己记着的上一份比，找出改了哪几条记录排队上传，再写浏览器缓存
```

启动时数据仓库调用 `load()`：读到就用；读不到（第一次用、格式版本对不上）就生成样例数据。没改过的样例数据隔天打开会按新的一天重新生成。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 接口只有 `load` / `save` 两个同步方法 | 在线版也先写浏览器缓存，保存结果当场就知道；上传云端在后台进行，另有同步状态 |
| `save` 只收改之后的完整数据，在线版自己记着上一份 | 数据仓库的修改都是「没改的记录保持原对象、改了的换新对象」，按对象是否相同就能找出改动的记录；由存储层自己记上一份，保存失败后重试也不会漏传改动 |
| 本地存储保留 `?fail=save` 演示开关 | 地址栏加上它，第一次保存会故意失败，用来检查失败提示和重试 |

## 当前实现

- `createStorage()` 目前两个版本都返回本地存储。
- 保存失败时数据仓库保留内存里的修改，失败次数加一，外框弹出「没能保存到本机」并给出重试。

## 验证方式

- `pnpm build:local && pnpm probe`：快速添加后刷新仍在、回顾笔记刷新后仍在。
- 地址加 `?fail=save` 做一次修改，出现保存失败提示，点重试后提示已保存。

## 待扩展项

- M2：云端存储实现（浏览器缓存 + 改动排队上传 + 拉取合并），以及把云端拉来的数据写回数据仓库的通道。

## 改动历史

- 2026-09-30：数据仓库不再直接写浏览器，改为只经过存储层；浏览器存储的键改为 `deverdesk:data`。
