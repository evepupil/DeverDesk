# AI 改动记录

- 模块定位：AI 每次改数据都打成一个「改动包」，记下谁、什么时候、为什么、每条改前改后；用户在页面里能看、能撤销，「只能提议」的令牌产生的改动要用户点采纳才生效。这是敢把数据交给 AI 管的前提。
- 对应代码：`worker/ai/`（`changesets.ts` 提交、采纳、拒绝、确认、撤销、撤回；`store.ts` 改动包的读写；`limits.ts` 限速和过期清理）、`worker/routes/ai.ts`（给页面用的接口）、`worker/migrations/0003_ai.sql`；页面在 `src/features/ai/`、`src/lib/ai-api.ts`
- 所属里程碑：[M4 MCP：让 AI 替你管（第一期）](../roadmap.md#m4)
- 界面规格：[前端设计 · 在线版的差异](../前端设计.md#在线版的差异)
- 当前状态：进行中
- 最近更新：2026-10-01

## 职责与边界

负责：把写工具交来的改动清单落库（立即生效、存成提议、先给预览三种走法）；冲突检查；改动包的列出、采纳、拒绝、确认、撤销、撤回；限速；30 天过期清理；页面上的 AI 动态入口、抽屉、今天页提议卡、AI 标记。

不负责：算出要改什么（[MCP 服务](MCP服务.md) 的各个工具）；令牌管理（[登录与令牌](登录与令牌.md)）。

## 状态流转

```
                    ┌──用户采纳──→ applied ──撤销──→ undone
写工具提交 ──只能提议档──→ proposed ──用户不要──→ rejected
          │                 └──AI 撤回──→ withdrawn
          ├──直接改档，普通改动──→ applied
          └──直接改档，删除或超过 10 条──→ preview ──AI 确认──→ applied
                                              └──15 分钟没确认──→ expired
```

- 一个改动包里每一条改动有自己的状态：`pending`（还没生效：提议、预览中）、`applied`、`conflict`（生效或撤销时发现记录已被人改过，跳过）、`undone`。
- 部分撤销：只撤其中几条时，改动包仍是 `applied`，被撤的那几条是 `undone`；全部已生效的都撤完，改动包变 `undone`。

## 数据表（迁移 0003）

`ai_changesets`：

| 字段 | 说明 |
| --- | --- |
| `id` | 文本主键，`cs_` 加 16 位随机字符 |
| `token_id` | 产生它的令牌（令牌删了也保留，用于记录） |
| `client_name` | 当时令牌的名称，例如「Claude Code」 |
| `tool` | 工具名，例如 `add_tasks`；页面接口写入的为 `rest:tasks`、`rest:ledger` |
| `reason` | AI 给的一句理由，可以为空 |
| `status` | 见状态流转 |
| `created_at`、`decided_at` | 毫秒时间；采纳、拒绝、确认、撤销、撤回、过期时记 `decided_at` |
| `decision_id` | 每次状态转换写入一个随机编号，同一个 batch 里后面的写入语句据此确认「这次转换是本请求做成的」 |

`ai_changes`：

| 字段 | 说明 |
| --- | --- |
| `changeset_id`、`seq` | 联合主键，`seq` 从 0 起按提交顺序 |
| `kind`、`record_id` | 改的是哪条记录 |
| `action` | `create` / `update` / `delete` |
| `before_data`、`before_updated_at`、`before_rev` | 改之前的内容（JSON）、修改时间、写入顺序号；库里从没有过为空 |
| `after_data`、`after_updated_at`、`after_rev` | 改之后的内容、写入时用的修改时间、写入后的写入顺序号；删除的内容为空；还没生效时后两项为空 |
| `state` | 见上 |

索引：`ai_changesets (created_at, id)`、`(status, created_at, id)`、`(token_id, created_at)`。

## 写入规则

1. **提交**：`submitChanges({ token, tool, reason, changes, forcePreview })`。`changes` 为空时直接返回 `no_change`，不建改动包。超过 20 条报错。
2. **走法**：只能提议档 → `proposed`；直接改档且（`forcePreview` 或超过 10 条）→ `preview`；其余 → 立即生效 `applied`。只看档不应走到这里（入口已拦）。
3. **生效一条改动**（立即生效、采纳、确认共用）：
   - **冲突检查用写入顺序号**（`rev`）：记录现在的写入顺序号必须等于提交时记下的 `before_rev`。不用修改时间判断，因为同步接口接受修改时间相同的写入，同一毫秒的两次写入会被误判成没人改过。
   - 新的修改时间 = max(现在, `before_updated_at` + 1)；库里从没有过用现在。
   - 新建、库里从没有过：`INSERT … ON CONFLICT DO NOTHING`，已存在同编号算冲突。
   - 新建、库里有已删除的同编号记录（例如计时器）：`ON CONFLICT DO UPDATE … WHERE records.deleted = 1 AND records.rev = before_rev`。
   - 修改、删除：`ON CONFLICT DO UPDATE … WHERE records.rev = before_rev`，记录在这之后被人改过就不动它，算冲突。删除写成内容为空、`deleted = 1`，和同步约定一致。
   - 写入顺序号沿用「当前最大值 + 1」，来源标 `api`；生效后把这条拿到的写入顺序号记进 `after_rev`（同一个 batch 里回填，思路：batch 开头记下当前最大写入顺序号，记录写完后，记录现在的写入顺序号大于它就说明这条生效了）。
   - 任务的显示编号：新建任务在生效那一刻按当前最大编号依次分配，写回 `after`。
   - 一个改动包的全部写入放进一次 `db.batch`，要么全写进要么全不写；冲突不报错，只是该条没有生效。
4. **改动明细**：`ai_changes` 用一条 `INSERT … SELECT … FROM json_each(?)` 一次写完（整包改动作为一个 JSON 参数），生效后再用一条语句回填写入顺序号、把冲突的几条标成 `conflict`。
5. **状态转换是原子的**：采纳、拒绝、确认、撤销、撤回、过期都写成「带预期状态的条件更新」，并和记录写入放在同一个 batch：第一条语句 `UPDATE ai_changesets SET status = 新状态, decided_at = ?, decision_id = <随机> WHERE id = ? AND status = 预期状态`，后面的记录写入都加条件「这个改动包现在的 `decision_id` 等于本次的随机编号」。第一条没改到行（别的请求已经处理过）时，后面的语句都不生效，接口回 `wrong_status`。同一个提议被两个页面同时采纳和拒绝、确认和过期清理撞在一起，都只会有一个成功。
6. **限速**：同一个令牌 10 分钟内提交的改动条数超过 200，拒绝并告诉 AI 还要等几分钟。几个请求同时到达时可能略微超出（检查和写入不是同一个原子操作），这是防 AI 失控的保险，不是精确配额，可以接受。
7. **提议里的时间按 AI 提交那一刻算**：例如提议「停止计时」，采纳后这段投入的结束时间是 AI 提交提议的时间（用户让 AI 停表的那一刻），不是点采纳的时间；任务的完成时间同理。采纳时不重新计算。
8. **AI 标记**：工具新建的任务、收支、投入记录在内容里带 `origin: "ai"`，页面据此画标记；采纳的提议同样带。
9. **过期清理**：每小时最多一次（在 `settings` 表记上次时间），删掉 30 天前的改动包和明细；把超过 15 分钟没确认的预览标成 `expired`；顺带执行 `PRAGMA optimize`，让 SQLite 收集统计信息、用上表达式索引（实测没有统计信息时它会退回按主键扫）。

## 撤销、采纳、拒绝、确认、撤回

| 操作 | 谁能做 | 对象状态 | 做法 |
| --- | --- | --- | --- |
| 采纳 | 页面（口令或 Access 登录） | `proposed` | 每条按「生效一条改动」写入；冲突的跳过；改动包变 `applied` |
| 拒绝 | 页面 | `proposed` | 改动包变 `rejected`，不写数据 |
| 确认 | AI（直接改档，同一个令牌） | `preview`，15 分钟内 | 同采纳 |
| 撤销 | 页面；AI（直接改档，只能撤自己令牌的） | `applied` | 按 `seq` 倒序处理选中的、状态为 `applied` 的改动：新建的删掉，修改的写回改前内容，删除的恢复改前内容；条件是记录当前写入顺序号仍等于 `after_rev`（之后没人改过），否则标 `conflict` 跳过；新的修改时间 = max(现在, `after_updated_at` + 1) |
| 撤回 | AI（提议档，同一个令牌） | `proposed` | 改动包变 `withdrawn` |

所有操作返回改动包的最新状态和冲突的 `seq` 列表；页面据此提示「有 N 条你之后改过，没有撤销」。

## 给页面用的接口

只认口令会话或 Access 身份，访问令牌一律 403（防止 AI 自己采纳自己的提议）。

| 接口 | 做什么 |
| --- | --- |
| `GET /api/ai/changesets?status=pending\|all&cursor=<游标>&limit=<1–50>` | 按 (创建时间, 编号) 倒序列出改动包（含明细），`pending` 只列等待采纳的提议；返回 `{ changesets, pendingCount, nextCursor }`，游标是不透明字符串，原样带回取下一页 |
| `POST /api/ai/changesets/<编号>/accept` | 采纳提议 |
| `POST /api/ai/changesets/<编号>/reject` | 不要这个提议 |
| `POST /api/ai/changesets/<编号>/undo`，体 `{ seqs?: number[] }` | 撤销整包或其中几条 |

返回类型 `ChangesetListResponse`、`ChangesetActionResponse` 定义在 `src/sync/protocol.ts`。采纳和撤销会改数据，页面收到结果后立刻触发一次同步。

| 位置 | 做法 |
| --- | --- |
| 窗口栏入口 | 同步图标左边一个 24px 见方的灰色图标按钮（`Sparkles` 图标），提示「AI 动态」；有等待采纳的提议时右上角一个数字角标：14px 高的小圆角块，深色底白字 10px，最小宽 14px，超过 9 显示「9+」 |

| 抽屉的状态 | 加载中三条灰块；读取失败给「重试」；没有记录时一句「还没有 AI 改动」；操作中按钮禁用并显示进行中；操作完成给一条提示，有冲突时写明几条没撤成、为什么 |
| 今天页提议卡 | 有等待采纳的提议时，今天页三栏上方一张横跨的卡：「Claude Code 提议：新建 3 个任务，挪动 2 个任务」，右侧「采纳」「不要」「查看」；不止一个提议时多一句「还有 2 个」，点「查看」打开抽屉的待采纳页；卡片用普通卡片的样式（白底、1px 边框、6px 圆角），左侧 3px 黄色竖条表示「等你处理」 |
| AI 标记 | 任务卡片辅助行、任务详情标题旁、收支行说明前、今天页投入列表的行里，AI 建的记录前放一个 12px 的 `Sparkles` 灰色图标，悬停提示「AI 记录」 |

记录名的取法：任务取标题；收支取备注，没有备注取「收入 / 支出 + 金额」；投入取「日期 开始–结束」；副业取名称；例行取标题；周笔记取「某周回顾」；作息设置、计时器取固定叫法。字段变化的显示名和值的格式沿用界面现有词条（状态叫法、日期格式、金额格式）。

刷新时机：抽屉打开时、窗口回到前台时、每 60 秒（只在页面可见时），以及采纳、拒绝、撤销之后。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 改动包存在服务器，不进同步记录 | 它是审计和撤销用的，不是工作台数据；不让每台设备都存一份 |
| 冲突检查用写入顺序号相等 | 只要用户在之后动过这条，AI 的改动和撤销都不覆盖用户的修改；写入顺序号每次写入都不同，不会像修改时间那样在同一毫秒撞上（规格评审指出） |
| 状态转换带预期状态、和记录写入同一个 batch | 同一个提议被同时采纳和拒绝时只有一个生效，不会出现「数据已写入但显示已拒绝」 |
| 提议里的时间不在采纳时重算 | 「停止计时」「完成任务」的时间以用户让 AI 去做的那一刻为准 |
| 列表游标用 (创建时间, 编号) | 只用时间做游标，同一毫秒的两个改动包跨页时会漏或重复 |
| 访问令牌不能调采纳接口 | 否则 AI 能自己批准自己的提议，「只能提议」形同虚设 |
| 明细用 `json_each` 一条语句写完 | 免费版每个请求的查询次数有限，20 条改动不能各占一条语句 |
| 保留 30 天 | 够用户回头查，又不让表无限变大 |
| 摘要文字由页面按语言拼 | 服务器不存某一种语言的文字，切换语言后显示照样对 |
