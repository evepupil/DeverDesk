# 同步

- 模块定位：在线版浏览器这一端。数据先存这台设备的缓存，改动排队上传，定时拉取别的设备的改动合并进来；断网照常能用，联网后自动补传。
- 对应代码：`src/state/storage/cloud.ts`（云端存储和同步引擎）、`src/state/storage/records.ts`（找出改动、合并记录的纯函数）、`src/state/sync.ts`（同步状态和调用入口）、`src/lib/api.ts`（接口调用）、`src/features/sync/sync-indicator.tsx`（窗口栏同步图标）
- 所属里程碑：[M2 在线版后端](../roadmap.md#m2)
- 界面规格：[前端设计 · 在线版的差异](../前端设计.md#在线版的差异)
- 当前状态：已完成
- 最近更新：2026-09-30

## 职责与边界

负责：把数据仓库的每次修改变成按条的改动排队上传；从云端拉取新写入的记录并合并；把合并结果交回数据仓库；对外报告同步状态。
不负责：服务器端的冲突裁决（见 [云端接口](云端接口.md)）、登录与退出的界面（见 [登录与令牌](登录与令牌.md)）、本地版的存储（见 [存储层](存储层.md)）。

## 结构与数据流

```
页面修改 → 数据仓库 → 存储层 save(改之后的数据)
                         ├─ ① 和上一份比，找出改了的记录 → 待上传队列（存本机）
                         └─ ② 整份写进本机缓存
      ③ 触发同步：改完 0.8 秒后、切回页面、联网、每 60 秒、点同步图标
                         ↓
               ④ 先分批上传（40 条一批）→ ⑤ 再从上次的位置分页拉取（500 条一页）
                         ↓
      ⑥ 云端退回的、别的设备写的 → 合并进本机缓存 → 交回数据仓库 → 页面更新
```

1. 数据仓库的修改都是「没改的记录保持原对象、改了的换新对象」，按对象是否相同就能找出改了哪几条；同一条在队列里只留最后一份。
2. 本机缓存和待上传队列分两个键存在浏览器里（`deverdesk:cloud-cache`、`deverdesk:cloud-outbox`），刷新、断网、关掉浏览器都还在。
3. 同一时间只跑一次同步；跑的时候又有新改动，跑完立刻再来一次。
4. 上传后，只有队列里那条的修改时间和刚传的一致才移出队列：上传途中又改了同一条，新改的留着下次传。
5. 拉取时跳过两种记录：队列里还没传上去的；这台设备已知的版本不比它旧的。
6. 合并按条替换，没动到的记录保持原对象，页面只重画变了的部分。

同步状态（窗口栏图标）：

| 状态 | 什么时候 | 图标上的提示 |
| --- | --- | --- |
| 已同步 | 上传完、拉取完 | 已同步 |
| 正在同步 | 同步进行中 | 正在同步 |
| 离线 | 连不上服务器 | 离线，N 条改动联网后上传 |
| 出错 | 服务器出错或本机写入失败 | 出错原因，点一下重试 |
| 登录过期 | 接口返回 401 | 不显示图标，回到登录页 |

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 本机缓存是工作基准，登录确认后才开始同步 | 打开就是上次的数据；断网也能进工作台 |
| 同步引擎跟着云端存储创建，登记到 `sync.ts`；界面只调 `sync.ts` 的函数 | 界面不依赖存储层的实现；本地版没有引擎，这些函数什么也不做 |
| 「开始同步」可以早于引擎登记，先记下来，登记时再开始 | 登录门比数据仓库先加载，不记下来会漏掉 |
| 打时间戳取「现在」和「这条已知最新时间 + 1」中较大的 | 设备时钟慢一点、或者云端有条时间超前的记录，之后在这台设备上改的照样算更新的 |
| 失败退避 5 / 15 / 60 秒；登录过期停下 | 不狂刷服务器；登录过期重试也没用 |
| 在线版从空白数据起步，不生成样例 | 样例只给演示站用；样例隔天会重新生成，放进在线版会被当成改动传上去 |
| 任务的内部编号改成随机串，给人看的编号用 `T-` + 序号 | 两台设备离线各建一件，内部编号不会撞 |
| 退出登录清掉本机缓存和队列，整页刷新 | 在别人的电脑上退出后不留数据；还有没传上去的改动时先确认 |

## 当前实现

- 首次登录的新设备：从空白数据起步，拉取云端全部记录；空白数据不会被当成改动传上去。
- 从本地版搬数据：在本地版导出备份，在线版导入；导入后全部记录按改动上传。
- 本机写入失败（浏览器存储满了等）：状态变成出错并退避重试，修改仍留在内存里。

## 验证方式

- `pnpm test`：`src/state/storage/records.test.ts` 覆盖找出改动、合并记录、两者往返一致。
- `pnpm build && pnpm e2e`：两台模拟设备互相同步、离线记一件联网后补传、同时改同一件以后改的为准、退出后缓存清掉。

## 待扩展项

- 两台设备离线各建一件任务时，显示编号可能相同（内部编号不同，不影响数据）；以后可在同步时发现重号再顺延。
- 大量数据时的首次拉取进度提示。
- 本机缓存改用 IndexedDB（浏览器里容量更大的数据库），突破 localStorage 约 5MB 的上限。
