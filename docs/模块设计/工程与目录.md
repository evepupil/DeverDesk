# 工程与目录

- 模块定位：整个仓库的工程基础——目录怎么分层、用什么工具、怎么验证。
- 对应代码：仓库根目录的配置文件、`src/` 分层、`worker/`、`scripts/`
- 所属里程碑：[M0 独立仓库](../roadmap.md#m0)
- 当前状态：已完成
- 最近更新：2026-09-30

## 职责与边界

负责：目录分层约定、构建与导出、本地开发命令、代码检查、单元测试、截图和交互核对脚本、许可证。
不负责：具体页面和数据逻辑（见各功能模块）。

## 结构与数据流

```
src/app/            路由，只放页面入口
src/features/       外框（shell）、各页面、共用部件（common）、表单（forms）
src/components/     ui = 改过尺寸的 shadcn 组件；base = 状态图形、标签、看板列等小部件
src/state/          数据仓库（store）、派生数据（hooks）、界面偏好（prefs）、浮层开合（ui）、同步状态（sync）、存储层（storage）
src/domain/         纯计算：排期、例行、收支、指标、回顾、快速添加解析、搜索、备份校验
src/data/           状态叫法和选项（catalog）、样例数据（seed，文案在 seed-text/ 按语言分）、固定种子随机数（rng）
src/styles/         设计令牌
src/lib/            版本开关（edition）、接口调用（api）、样式常量、表格导出等小工具
src/i18n/           多语言：语言设置、取词条、各语言词条（messages/）
src/sync/           前后端共用的同步约定（记录种类、接口路径、请求和返回的格式）
worker/             在线版接口：入口、路由、身份校验、数据库读写、建表语句
scripts/            本地开发（dev.mjs）、按版本打包（build.mjs）、导出后处理、样例数据概况、离线截图与交互核对、在线版端到端核对、README 截图（readme-shots.mjs）
.github/workflows/  持续集成：每次推送和 Pull Request 自动跑检查和打包
deploy/demo/        本地版演示站的部署配置
```

依赖方向只能从上往下：页面 → 状态 → 计算；计算层不引用界面和状态。`worker/` 只引用 `src/sync/` 和 `src/domain/`，不引用界面和状态。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 从实验仓库迁出，只带工作台 | 实验仓库里还有一个经营后台示例，和本产品无关；一键部署也要求仓库或子目录完全独立 |
| 迁移时去掉「workbench」这一层目录 | 只剩一个工作区，多一层目录只会让路径变长 |
| 浮层开合、界面偏好各合成一个状态 | 原来外框和页面各有一份，同名字段容易混 |
| 页面导出成静态文件 | 本地版任何静态托管都能放；在线版由 Worker 托管同一批文件 |
| 浏览器存储的键统一用 `deverdesk:` 开头 | 和同域名下的其他应用分开 |
| 开发时放行的外部域名走环境变量 | 仓库公开，不写死个人隧道域名 |
| AGPL-3.0 许可证 | 可以自由使用和自部署；别人改了拿去做在线服务也要公开代码 |
| `pnpm dev` 一条命令同时起页面和接口 | 页面走 Next 开发服务器，`/api` 转给 wrangler 起的本地接口，本地数据库自动建表；第一次运行自动生成本地口令 `dev` |
| 开发时接口进程的静态资源目录用单独的空目录 | 挂着打包目录 `out/` 的话，Windows 上接口进程会占着它，开着开发服务器时打包报「资源被占用」 |
| README 英文为主页、中文单独一份，两边互链 | 开源项目面向全球开发者，英文放仓库首页；中文用户点一下就到中文版 |
| 持续集成只跑类型检查、代码检查、单元测试和两个版本的打包 | 交互核对和端到端核对依赖本机 Edge 浏览器、耗时长，放在本地按改动范围跑 |
| 单元测试用 vitest，测试文件放在被测文件旁边 | 和 Vite 生态一致、启动快；`worker/` 的测试直接用 Node 自带的 Web Crypto |

## 当前实现

- Next.js 16 静态导出；导出后用 `scripts/flatten-segments.mjs` 修正 Windows 下预取文件的路径。
- 严格模式的 TypeScript；页面和 `worker/` 各有一份类型配置（Worker 用 Cloudflare 的运行时类型），`pnpm typecheck` 两份都查。
- ESLint 用 Next 自带规则。
- 开源仓库的门面：英文 `README.md`、中文 `README.zh-CN.md`、贡献指南 `CONTRIBUTING.md`、安全说明 `SECURITY.md`；README 截图在 `docs/assets/screenshots/`，用 `pnpm shots:readme` 重新生成。
- 持续集成（`.github/workflows/ci.yml`）：推送到 main 和每个 Pull Request 都跑类型检查、代码检查、单元测试，再把两个版本各打包一次。
- 换行统一 LF（`.gitattributes`）。

## 验证方式

```bash
pnpm typecheck && pnpm lint && pnpm test
pnpm build && pnpm e2e            # 在线版：本机起接口，两台模拟设备核对登录和同步
pnpm build:local && pnpm probe    # 交互核对跑本地版的打包结果
pnpm shots                        # 各页面、各宽度截图
```
