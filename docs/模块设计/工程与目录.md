# 工程与目录

- 模块定位：整个仓库的工程基础——目录怎么分层、用什么工具、怎么验证。
- 对应代码：仓库根目录的配置文件、`src/` 分层、`scripts/`
- 所属里程碑：[M0 独立仓库](../roadmap.md#m0)
- 当前状态：已完成
- 最近更新：2026-09-30

## 职责与边界

负责：目录分层约定、构建与导出、代码检查、截图和交互核对脚本、许可证。
不负责：具体页面和数据逻辑（见各功能模块）。

## 结构与数据流

```
src/app/            路由，只放页面入口
src/features/       外框（shell）、各页面、共用部件（common）、表单（forms）
src/components/     ui = 改过尺寸的 shadcn 组件；base = 状态图形、标签、看板列等小部件
src/state/          数据仓库（store）、派生数据（hooks）、界面偏好（prefs）、浮层开合（ui）、本地存储工具
src/domain/         纯计算：排期、例行、收支、指标、回顾、快速添加解析、搜索、备份校验
src/data/           状态叫法和选项（catalog）、样例数据（seed）、固定种子随机数（rng）
src/styles/         设计令牌
src/lib/            版本开关（edition）、样式常量、表格导出等小工具
scripts/            按版本打包（build.mjs）、导出后处理、样例数据概况、离线截图与交互核对
deploy/demo/        本地版演示站的部署配置
```

依赖方向只能从上往下：页面 → 状态 → 计算；计算层不引用界面和状态。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 从实验仓库迁出，只带工作台 | 实验仓库里还有一个经营后台示例，和本产品无关；一键部署也要求仓库或子目录完全独立 |
| 迁移时去掉「workbench」这一层目录 | 只剩一个工作区，多一层目录只会让路径变长 |
| 浮层开合、界面偏好各合成一个状态 | 原来外框和页面各有一份，同名字段容易混 |
| 页面导出成静态文件 | 本地版任何静态托管都能放；在线版由 Worker 托管同一批文件 |
| 浏览器存储的键统一用 `deverdesk:` 开头 | 和同域名下的其他应用分开 |
| 开发时放行的外部域名走环境变量 | 仓库公开，不写死个人隧道域名 |
| AGPL-3.0 许可证 | 可以自由使用和自部署；别人改了拿去做在线服务也要公开代码 |

## 当前实现

- Next.js 16 静态导出；导出后用 `scripts/flatten-segments.mjs` 修正 Windows 下预取文件的路径。
- 严格模式的 TypeScript；ESLint 用 Next 自带规则。
- 换行统一 LF（`.gitattributes`）。

## 验证方式

```bash
pnpm typecheck && pnpm lint && pnpm build
pnpm build:local && pnpm probe    # 交互核对跑本地版的打包结果
pnpm shots                        # 各页面、各宽度截图
```
