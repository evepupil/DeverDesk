# 官网

- 模块定位：DeverDesk 的对外官网，讲清产品是什么、引导试用和自己部署、体现全部开源；有首页、更新日志、博客列表、博客文章四类页面，中文、英文两套地址。
- 对应代码：`site/`（独立的 Next.js 项目，自己的依赖和锁文件）。路由在 `site/src/app/`，共享组件在 `site/src/components/site/`，Aceternity 组件在 `site/src/components/aceternity/`，各页区块在 `site/src/sections/`，语言与词条在 `site/src/i18n/`（根地址的服务端跳转也在这里：`root-redirect.ts`），数据在 `site/src/content/`，博客文章在 `site/content/blog/`，产品截图和博客封面在 `site/public/`，截图与核对脚本在 `site/scripts/`，只管根地址的 Worker 入口在 `site/worker/`。
- 所属里程碑：[M5 官网](../roadmap.md#m5)
- 界面规格：[前端设计：官网](../前端设计-官网.md)
- 当前状态：已完成，已上线 https://deverdesk.com （www.deverdesk.com 同样可以打开）
- 最近更新：2026-10-01

## 职责与边界

负责：官网的全部页面、中英文两套文字、页面语言的选择和切换（含根地址的服务端跳转）、更新日志和博客内容的展示、打包时读取 GitHub 仓库的星数和最近提交、站点地图和爬虫规则、官网的访问统计、官网自己的部署配置。
不负责：产品本身（工作台在仓库根目录，官网只放它的截图）；演示站（`app.deverdesk.com`，部署配置在 `deploy/demo/`）。

## 结构与数据流

```
打开 deverdesk.com/
  └─ Worker（site/worker/index.ts，只接根地址）：Cookie 里记过的语言 → 请求头 Accept-Language 里有 zh 开头的 → 其余英文，
     302 跳到 /zh/ 或 /en/（查询参数带过去；访客原来的来源浏览器会一并带过去）
     放到别的静态托管、没有 Worker 时：根地址页面里的兜底脚本按同样的规则跳（来源会丢）
/zh/…、/en/…（每种语言一套静态页面，不经过 Worker）
  ├─ 页面文件：取语言 → 顶栏 + 各区块 + 页脚
  ├─ 区块：getMessages(语言) 取文字；src/content/* 取数据（首页结构、更新日志、截图地址、技术栈图标）
  ├─ 博客：打包时读 content/blog/<文章>/<语言>.md → 头信息 + 正文转 HTML + 抽出目录
  ├─ 开源区块和顶栏：打包时向 GitHub 接口要一次星数和最近 5 次提交，要不到就用快照
  └─ 访问统计：打包时配了令牌，各语言页面和 404 页加载 Cloudflare 网页统计脚本，数据报到 Cloudflare 后台
打包（pnpm build）→ out/ 静态文件 → 部署成 Cloudflare Worker「deverdesk-site」：静态资源 + 只管根地址的 Worker（site/wrangler.jsonc，绑 deverdesk.com 和 www.deverdesk.com）
```

| 页面 | 区块 |
| --- | --- |
| 首页 | 顶栏、首屏（小字链接、大标题、在线试用 / 部署按钮、光带、浏览器框里的「今天」页截图）、技术栈 12 个开源项目、功能 Bento（今天的时间线、按阶段管理副业、待到账提醒、一行快速添加 + 6 个小功能）、产品导览（8 个页面的页签切换）、两种用法（手机电脑平板 + 本地版 / 在线版 / 数据归属三张卡，在线版卡里是 Aceternity 世界地图）、开源（仓库卡、终端命令、最近 5 次提交、许可证）、场景墙（十件经营一人公司每天会碰到的事轮流点亮）、常见问题（产品、部署、开源三组共 11 题）、收尾（截图拼贴）、页脚 |
| 更新日志 | 页头（版本数、最近更新、版本跳转）、Aceternity 时间线（5 个版本，每条有摘要、改动清单、截图和对应的 GitHub 提交）、关注更新 |
| 博客列表 | 页头（方格底纹、文章数）、置顶文章大卡、更多文章（搜索框 + 标签筛选 + 一行一篇 + 空结果） |
| 博客文章 | 返回链接、左侧目录（滚动时高亮当前章节）、封面、标题和信息、正文、作者行、在 GitHub 上编辑这篇、上一篇 / 下一篇、收尾卡 |

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 官网放在仓库的 `site/` 目录，是独立的 pnpm 项目 | 官网的代码也开源；和产品各管各的依赖和打包，一键部署产品时不会装官网的依赖。仓库根目录的类型检查和代码检查排除 `site/` |
| 地址按语言分（`/zh/`、`/en/`），每种语言导出一套静态页面 | 搜索引擎能分别收录两种语言；页面带 hreflang 互相指向 |
| 根地址由 Worker 在服务端选语言、302 跳转；页面里的脚本跳转只留作兜底 | 用脚本跳，统计会把来源记成官网自己、访问次数也少算（大部分人从根地址进来）；服务端跳转浏览器会保留原来的来源，也更快。Worker 只接根地址，其余地址照旧直接给静态文件，免费额度够用。服务端和兜底脚本共用 pickLocale，逐条对照测试 |
| 记住的语言存 Cookie（`deverdesk-site-locale`，一年） | 服务端读不到浏览器本地存储，Cookie 两边都读得到 |
| 访问统计用 Cloudflare 网页统计（Web Analytics），令牌打包时从环境变量读 | 免费；站点本来就在 Cloudflare，后台直接看；统计本身不用 Cookie、不记个人信息，不用弹同意框。令牌不进仓库，本地预览、持续集成、fork 出去的官网都不统计 |
| 新窗口链接的 rel 统一由 `externalRel` 给：去自家仓库和演示站的只写 noopener，其余加 noreferrer | 浏览器默认只把「从 deverdesk.com 来」告诉对方（不带具体页面），GitHub 流量页和演示站的统计才数得到官网带去多少人；别家网站仍不告诉来源 |
| 自己写一层很薄的词条机制，英文词条的类型从中文推出来 | 和产品同一种做法；漏翻、多翻由类型检查拦下，数组长度和占位由单测核对；组件里写死的中文由源码扫描测试拦下 |
| 照付费模板的版式复刻，用 Aceternity 免费组件（Timeline、Code Block、World Map）加自己写的插画 | 模板和博客区块是付费的，代码拿不到；版式和数值照公开预览逐项量出来 |
| 产品截图用脚本从产品本地版的打包结果里截，中英文各一套 | 截图永远是真界面，产品改版后重跑一次脚本即可 |
| GitHub 星数、最近提交在打包时取，拿不到用快照；星数少于 100 不显示数字（顶栏和仓库卡一样），分支数为 0 时不显示 | 静态站不在访客浏览器里请求 GitHub；新项目星数少时只写「Star」，不显得冷清 |
| 更新日志的版本号就是仓库的 Git 标签，每个标签有一条同名的 GitHub Release | 官网、标签、Release 用同一组版本号，读者在哪里看到的都一样。标签打在这一版所列提交里最新的那个上，上一版标签到这一版标签之间的提交正好是页面上列的提交。加新版本时，先在 `site/src/content/changelog.ts` 写一条，再打同名标签、发 Release（说明取这条数据的中英文） |
| 「在线试用」都在当前页打开演示站，GitHub 等站外链接新窗口打开 | 试用是官网的主动作；站外参考资料不打断浏览 |
| 只有浅色 | 产品本身只有浅色，截图放暗底上反差太大 |
| 定位：首屏写「独立开发者的专业工作台」，其余文案围绕「一人公司的专业工作台」 | 产品能管任务、副业、收支、时间、例行和回顾，卖点是「经营一人公司要做的事都在一处、而且专业」；时薪只是副业和概览里的一个指标，不单独当卖点 |
| 语言切换用经典下拉（地球图标 + 当前语言 + 小箭头） | 一眼能认出是切语言；以后加语言不用改顶栏的宽度 |
| 判断「减少动态效果」用自己的钩子（服务端和接管那一次都当作没开） | motion 自带的判断在服务端和浏览器第一次渲染时不一致，会报水合错误 |

## 当前实现

- Next.js 16 静态导出（`trailingSlash`），Tailwind 4，motion 做动效，@tabler/icons-react 做图标，Inter 字体随站点打包。
- 路由：`(root)` 根布局只放根地址的兜底跳转页；`[locale]` 根布局放各语言页面；`global-not-found.tsx` 出中英双语 404；`sitemap.ts`、`robots.ts` 打包时生成。
- 根地址跳转：`site/worker/index.ts` 只有一行分流，根地址交给 `src/i18n/root-redirect.ts`，其余交回静态资源；`wrangler.jsonc` 里 `run_worker_first: ["/"]`，只有根地址会调用 Worker。跳转回 302，带 `Cache-Control: no-store` 和 `Vary: Accept-Language, Cookie`，HEAD 也跳，别的请求方法不管。
- 访问统计：`components/site/analytics.tsx` 用 next/script 在页面可交互后加载 `static.cloudflareinsights.com/beacon.min.js`，放在 `[locale]` 根布局和 404 页（404 页能看出外面有哪些坏链接指进来）；根地址兜底页不放。令牌是 `site/.env.production.local` 里的 `NEXT_PUBLIC_ANALYTICS_TOKEN`（不提交），没配时不渲染。Cloudflare 后台 Web Analytics 里是 deverdesk.com 这一个站点，用手动加脚本的模式（Enable with JS Snippet installation），演示站用同一个令牌，看数据时按主机名（Host）分开。
- 共享组件：顶栏（顶部透明，往下滚藏起、往上滚变悬浮圆角条，手机菜单）、语言切换（记住选择）、GitHub 按钮、页脚（四列链接、在 GitHub 上编辑此页、超大描边品牌字）、浏览器框、截图、区块标题、访问统计等。
- 新窗口链接：全站新窗口打开的链接（包括博客正文里的站外链接）都用 `lib/links.ts` 的 `externalRel(地址)` 取 rel。
- 首屏大标题「独立开发者的专业工作台」（英文 The professional workbench for indie developers），「的」后面放了一个看不见的换行点，窄屏时断成两行；功能区第二张卡是副业管理（阶段、本月净收入、月目标进度）。
- 语言切换是顶栏、手机菜单、页脚共用的一个下拉：选中后把语言写进 Cookie 记住，再点当前语言只收起菜单。
- 词条约 400 条，中英文逐条对应；博客 5 篇，每篇中英文各一份（`why-deverdesk` 置顶）。
- 产品截图 18 张（8 个页面 × 2 种语言 + 手机版 × 2），WebP，共约 2.8MB；博客封面 5 张由生图工具生成。

## 验证方式

在 `site/` 里：

```bash
pnpm test            # 58 条：语言选择、Cookie 与 Accept-Language 解析、根地址服务端跳转、兜底跳转脚本、站外链接的 rel、词条对齐、写死中文扫描、格式化、GitHub 数据解析、更新日志、博客内容
pnpm typecheck && pnpm lint
SITE_OFFLINE=1 pnpm build   # 离线打包：不向 GitHub 要星数，提交用快照
pnpm probe           # 交互核对 40 项：顶栏滚动与菜单、语言下拉与切换、导览页签与键盘、场景墙、常见问题、更新日志跳转、博客筛选搜索与目录、根地址跳转、404、手机与桌面不横向溢出
pnpm shots           # 各页中英文、手机与桌面截图 + 交互状态截图，输出到 scripts/acceptance/.shots/
pnpm shots:app       # 重截产品截图（先在仓库根目录 pnpm build:local）
```

`pnpm probe` 直接读 `out/`，根地址走的是兜底脚本；核对时站外请求（包括统计脚本）一律拦掉，不往统计后台报数。Worker 的服务端跳转除了单测，再用 wrangler 本地跑一遍：

```bash
node ../node_modules/wrangler/bin/wrangler.js dev --port 8791   # 在 site/ 里，先打包
curl -sI -H "Accept-Language: zh-CN" http://127.0.0.1:8791/     # 302，Location 是 /zh/
curl -sI -H "Cookie: deverdesk-site-locale=zh" -H "Accept-Language: en" http://127.0.0.1:8791/   # 记过中文 → /zh/
```

持续集成里有单独的 `site` 任务：安装、单测、类型检查、代码检查、离线打包。

上线：先确认 `site/.env.production.local` 里有统计令牌（`NEXT_PUBLIC_ANALYTICS_TOKEN=…`，没有就不统计），在 `site/` 里 `pnpm build`（联网打包，页面里的星数和最近提交取 GitHub 的真实数据；**先把代码推到 GitHub**，否则「最近提交」和「在 GitHub 上编辑此页」对不上），再 `pnpm run deploy`（用 wrangler 部署，配置里已经绑好两个域名）。看数据：Cloudflare 后台 → Web Analytics → deverdesk.com，按 Host 选 deverdesk.com / www.deverdesk.com。
