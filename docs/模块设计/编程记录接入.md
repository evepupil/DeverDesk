## 职责与边界

负责：钩子怎么配、怎么传凭据、插件怎么打包分发、Codex 怎么接、装完怎么确认它在工作。

不负责：事件怎么变成任务（[本机记录器](本机记录器.md)、[编程自动记录](编程自动记录.md)）。

## 钩子负载

### Claude Code（实测，标准输入的 JSON）

| 事件 | 字段 |
| --- | --- |
| 公共 | `session_id`、`transcript_path`、`cwd`、`hook_event_name` |
| `SessionStart` | + `source`（`startup` / `resume` / `clear` / `compact`），可选 `model`、`agent_type` |
| `UserPromptSubmit` | + `prompt_id`、`permission_mode`、`prompt` |
| `PostToolUse` | + `prompt_id`、`permission_mode`、`tool_name`、`tool_input`（Bash 时有 `command`）、`tool_response`、`tool_use_id`、`duration_ms` |
| `Stop` | + `prompt_id`、`permission_mode`、`stop_hook_active`、`last_assistant_message`、`background_tasks`、`session_crons` |
| `SessionEnd` | + `prompt_id`、`reason` |

环境里有：`CLAUDE_PROJECT_DIR`（正斜杠路径）、`CLAUDE_CODE_SESSION_ID`、`CLAUDE_CODE_ENTRYPOINT`；`SessionStart` 里还有 `CLAUDE_ENV_FILE`。`CLAUDE_CODE_SESSION_ATTENDED` 在通过 Agent SDK 的宿主（如 codeg）里有人聊天时也是 0，**不用它判断有没有人在**。

钩子在 Windows 上默认用 Git Bash 执行；`UserPromptSubmit` / `Stop` 的标准输出会被加进 AI 的上下文，所以记录器在这些事件里一个字也不输出。

### Codex

Codex 现在有和 Claude Code 几乎一样的生命周期钩子（`SessionStart`、`UserPromptSubmit`、`Stop`、`SessionEnd`、`PostToolUse` 等），从标准输入读 JSON，公共字段 `session_id`、`transcript_path`、`cwd`、`hook_event_name`、`model`。用户级配置放 `~/.codex/hooks.json`（顶层要有 `hooks` 键）或 `config.toml` 里的 `[hooks]`。旧的 `notify` 只在每轮结束触发一次，不用。适配器按「字段缺了就跳过那个事件」写：`session_id` 取 `session_id`，没有就取 `thread_id`；`prompt` 取 `prompt`；`Stop` 的摘要取 `last_assistant_message`。**未在真实 Codex 上验证**（本机约定不能同时再起一个 Codex），用官方文档里的样例做单测，验收时由用户在真实 Codex 上确认。

Codex 会话记录文件（回填用）：`$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<时间>-<会话编号>.jsonl`，每行 `{ type, timestamp, ordinal, payload, metadata }`，`timestamp` 是带毫秒的 UTC ISO 字符串。`type` 取值：`session_meta`（`payload.cwd`、`payload.id`、`payload.git.commit_hash/branch/repository_url`）、`event_msg`（`payload.type` 为 `task_started` 表示开始处理你的一次输入，`task_complete` 表示这一轮结束，带 `completed_at`、`duration_ms`、`last_agent_message`）、`response_item`、`turn_context` 等。回填规则：`task_started` → `prompt`，`task_complete` → `stop`，`session_meta` → `start`，时间一律取行的 `timestamp`；`codex exec` 非交互会话同样处理。

## Claude Code 插件

插件根目录是 `integrations/claude-code/`：

```
integrations/claude-code/
  .claude-plugin/plugin.json
  .mcp.json
  hooks/hooks.json
  skills/deverdesk/SKILL.md
  bin/deverdesk-recorder          # 构建产物（提交进仓库），也是 Bash 工具 PATH 上的命令
  README.md
```

仓库根目录另有 `.claude-plugin/marketplace.json`，让整个仓库可以当作插件市场添加。

### `plugin.json`

```json
{
  "name": "deverdesk",
  "displayName": "DeverDesk",
  "version": "0.1.0",
  "description": "Connect Claude Code to your DeverDesk and record coding time and tasks automatically.",
  "author": { "name": "DeverDesk" },
  "homepage": "https://deverdesk.com",
  "repository": "https://github.com/evepupil/DeverDesk",
  "license": "AGPL-3.0-only",
  "keywords": ["time-tracking", "mcp", "deverdesk"],
  "userConfig": {
    "server_url": {
      "type": "string", "title": "DeverDesk address", "required": true,
      "description": "Your cloud edition address without a trailing slash, e.g. https://deverdesk.example.com"
    },
    "token": {
      "type": "string", "title": "Access token", "required": true, "sensitive": true,
      "description": "Create one in DeverDesk: avatar menu → Connect AI. Pick the Write permission."
    }
  }
}
```

启用插件时 Claude Code 会向用户询问这两项；令牌存进系统安全存储。钩子进程里它们是环境变量 `CLAUDE_PLUGIN_OPTION_SERVER_URL`、`CLAUDE_PLUGIN_OPTION_TOKEN`。

### `.mcp.json`（顺带把 MCP 连接配好）

```json
{
  "mcpServers": {
    "deverdesk": {
      "type": "http",
      "url": "${user_config.server_url}/mcp",
      "headers": { "Authorization": "Bearer ${user_config.token}" }
    }
  }
}
```

### `hooks/hooks.json`

全部用「命令加参数」的写法（不经过 shell，Windows 上没有引号问题，也才能拿到上面的插件选项环境变量）。不影响你发话和 AI 收尾的事件设成后台运行（`async: true`）：

```json
{
  "description": "Record coding time and tasks to ~/.deverdesk",
  "hooks": {
    "SessionStart": [{ "hooks": [
      { "type": "command", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "SessionStart"], "timeout": 5 }
    ]}],
    "UserPromptSubmit": [{ "hooks": [
      { "type": "command", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "UserPromptSubmit"], "async": true }
    ]}],
    "Stop": [{ "hooks": [
      { "type": "command", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "Stop"], "async": true }
    ]}],
    "SessionEnd": [{ "hooks": [
      { "type": "command", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "SessionEnd"], "timeout": 3 }
    ]}],
    "PostToolUse": [{ "matcher": "Bash", "hooks": [
      { "type": "command", "if": "Bash(git commit *)", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "PostToolUse"], "async": true },
      { "type": "command", "if": "Bash(git -C * commit *)", "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/bin/deverdesk-recorder", "hook", "claude-code", "PostToolUse"], "async": true }
    ]}]
  }
}
```

- `SessionStart` 不能后台运行：它的输出是给 AI 的简报，要等它。
- `SessionEnd` 总共只有 1.5 秒预算，记录器只追加一行并后台启动同步。
- `PostToolUse` 靠 `if` 只在 Bash 命令是 `git commit …` 时才启动进程；其他提交方式靠 `Stop` 兜底。同一次提交被两个钩子都发现时，按提交号去重。

### `bin/deverdesk-recorder`

构建产物，开头 `#!/usr/bin/env node`，CommonJS。钩子用 `node <路径>` 启动；插件启用后 `bin/` 在 Bash 工具的 PATH 上，AI 可以直接运行 `deverdesk-recorder done "…"`、`deverdesk-recorder status`。

### 技能 `skills/deverdesk/SKILL.md`

英文写（AI 读），描述里带上中英文触发词（「把这个项目加进 DeverDesk」「算到某某副业」「link this folder to DeverDesk」）。正文只讲三件事，每件三五行：

1. **绑定当前文件夹**：运行 `deverdesk-recorder status --json` 拿 `dir`（目录名）和是否已绑定；调用 DeverDesk 的 `list_projects` 看有哪些副业；用户指明了已有副业就 `manage_project`（`action: update`，`addDirectories: [dir]`），否则 `manage_project`（`action: create`，`name` 用 `dir`，`directories: [dir]`）；告诉用户绑定后以前的记录下次同步会补上去。解绑同理用 `removeDirectories`。
2. **报告做完**：做完一件没有提交的实质工作（调研、排查、写文档不提交）后，运行 `deverdesk-recorder done "<一句话标题>"`。有提交的工作不用报告。
3. **提交说明里写任务编号**：这次工作对应 DeverDesk 里已有的任务（会话开始的简报里列了编号），提交说明第一行或 `Closes T-123` 里写上编号，该任务会被标成完成。

技能的 frontmatter 声明 `allowed-tools: Bash(deverdesk-recorder *)`，运行记录器命令不再弹权限确认。

## 分发与安装

用户的两条命令：

```bash
claude plugin marketplace add evepupil/DeverDesk
claude plugin install deverdesk@deverdesk
```

装完启用时按提示填「DeverDesk 地址」和「访问令牌」。更新：`claude plugin marketplace update` 再 `claude plugin update deverdesk@deverdesk`（2.1.276 里 `plugin update` 要明确带 `--scope`）。

本机开发和端到端测试：`claude --plugin-dir ./integrations/claude-code`（这种方式没有 `userConfig` 提示，凭据走环境变量 `DEVERDESK_URL` / `DEVERDESK_TOKEN`）。校验：`claude plugin validate ./integrations/claude-code` 和仓库根目录的市场文件。

「连接 AI」弹窗新建令牌后，客户端分段新增「记录器」，显示：

1. 上面两条安装命令；
2. 填写项提示（地址填什么、令牌就是刚建的那个）；
3. Codex 或手动安装用的一条命令：`deverdesk-recorder setup --url <地址> --token <令牌>`（用插件时不需要）。

## Codex

- 钩子配置写在 `~/.codex/hooks.json`：

```json
{ "hooks": {
  "SessionStart":     [{ "hooks": [{ "type": "command", "command": "node \"<路径>/deverdesk-recorder\" hook codex SessionStart" }] }],
  "UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "node \"<路径>/deverdesk-recorder\" hook codex UserPromptSubmit" }] }],
  "Stop":             [{ "hooks": [{ "type": "command", "command": "node \"<路径>/deverdesk-recorder\" hook codex Stop" }] }],
  "SessionEnd":       [{ "hooks": [{ "type": "command", "command": "node \"<路径>/deverdesk-recorder\" hook codex SessionEnd", "timeout": 3 }] }]
} }
```

- `deverdesk-recorder setup --install-codex-hooks`：把上面四项合并进已有的 `hooks.json`（已有的其他钩子原样保留，先备份成 `hooks.json.bak-<时间>`），`<路径>` 是这个可执行文件自己的绝对路径。Codex 可能要求你在第一次使用时确认信任这些钩子。
- 凭据：Codex 没有插件选项，用 `config.json`（`setup --url --token` 写入）。
- Codex 的 MCP 连接配置沿用「连接 AI」弹窗里已有的 Codex 段。
- Windows 和 WSL 共用同一个 `CODEX_HOME` 时，`hooks.json` 里的命令路径只有一边有效；记录器的日志也在各自系统的家目录里（WSL 里是 `/home/<用户>/.deverdesk`），两边各记各的、各自上传，互相不平分。需要两边都记，就在两边各装一份并改用 PATH 里的命令名。

## 验证方式

- 单测：Claude Code 和 Codex 的负载解析用上面的真实样例（Claude Code 的样例来自 2026-10-02 本机实测，去掉了路径里的个人信息）；`doctor` 的判断；`setup --install-codex-hooks` 合并 `hooks.json` 不丢已有钩子。
- 插件校验：`claude plugin validate ./integrations/claude-code`。
- 真实会话端到端（`scripts/acceptance/e2e-recorder.mjs`）：本机起 Worker 和临时数据库，建一个绑定了临时目录名的副业和「直接改」令牌；在临时 git 仓库里用 `claude -p --model haiku --plugin-dir …` 跑一次「写一个文件并提交，提交说明里写 T-1xx」；断言：事件日志里有 `start`、`prompt`、`stop`、`commit`、`end`；`sync` 之后服务器上有一个已完成任务（或 T-1xx 被标成完成）、时间段分钟合理；再跑一次不产生新记录；未绑定目录名的会话一条都没上传。
- 并行：同时开两个 `claude -p` 会话（不同临时目录），断言两边分钟数之和不超过真实流逝时间。
- 宿主差异：在 codeg（通过 Agent SDK 的宿主）里，用户装好插件后跑 `deverdesk-recorder doctor`，看「最近一次钩子触发」是否出现 `claude-code` 的事件；这一项只能在用户机器上验收。

## 已知限制

- 两台电脑同时在写：各算各的，不合并平分。
- 没有提交又没有结束会话的工作，要到下一次有钩子触发（任何会话）才收成任务；页面上的「进行中」不受影响（它由最近一次同步更新，5 分钟没更新就自动消失）。
- Codex 部分未在真实 Codex 上验证；Windows 与 WSL 共用 `CODEX_HOME` 时见上。
- 宿主不加载插件钩子时（例如某些 Agent SDK 宿主默认不读用户配置）没有任何记录；`doctor` 会告诉你。
