# 编程自动记录

- 模块定位：用 AI 写代码时自动记工时和任务。本机记录器跟着 Claude Code、Codex 的会话记下「几点、在哪个项目、发生了什么」，按规则算出每件事用了多久；目录绑定了副业的，同步到 DeverDesk，变成已完成任务和投入时间。
- 对应代码：`integrations/recorder/`（本机记录器：规则引擎、本机存储、命令行）、`integrations/claude-code/`（Claude Code 插件）、`worker/recorder/`（服务器接口）、`src/features/projects/`（目录名设置）、`src/features/today/`（投入列表）
- 所属里程碑：[M6 编程自动记录](../roadmap.md#m6)
- 子文档：[本机记录器](本机记录器.md)（事件、存储、命令、钩子、回填）、[编程记录接入](编程记录接入.md)（Claude Code 插件、Codex、安装）、[编程记录接口与显示](编程记录接口与显示.md)（服务器接口、数据变化、页面）
- 当前状态：进行中（设计已和用户定稿，规格补全中）
- 最近更新：2026-10-02

## 职责与边界

负责：认出会话属于哪个项目；记下会话里的动静；按规则把时间分到项目和任务；用提交切分任务；绑定后上传；没绑定的只留在本机。

不负责：手敲代码（没有 AI 会话）的计时；服务器上的任务、投入怎么存（沿用现有记录，见 [云端接口](云端接口.md)）。

## 一句话流程

```
Claude Code / Codex 的钩子 ──→ 本机记录器 ──→ ~/.deverdesk/ 里的事件日志（所有目录都记，永远留在本机）
                                    │
                         sync：从日志算出「到站的任务」
                                    │ 只挑已绑定副业的目录
                                    ▼
                         POST /api/recorder/upload ──→ 已完成任务 + 投入时间（带「自动记录」标记）
```

## 认项目：只看文件夹名

一条规则：

- 用了 git：问 git「这个仓库本体在哪」，取本体所在文件夹的名字；
- 没用 git：取会话所在文件夹的名字。

做法（`git rev-parse --path-format=absolute --git-common-dir`，注意这个开关要写在前面才生效）：

| 情形 | 判断 | 目录名 |
| --- | --- | --- |
| 普通仓库或它的子文件夹 | 公共目录是 `<仓库>/.git` | 仓库文件夹名 |
| 派活开的额外工作目录（worktree） | 公共目录指回主仓库的 `.git` | 主仓库文件夹名 |
| 子模块 | 公共目录在 `<上级>/.git/modules/…`，且 `--show-superproject-working-tree` 非空 | 子模块自己文件夹名（`--show-toplevel`） |
| 裸仓库（`foo.git`） | 公共目录不以 `.git` 结尾的文件夹名，或本身叫 `xxx.git` | 去掉 `.git` 后缀的名字 |
| 没用 git，或 git 不可用 | — | 会话所在文件夹名 |
| WSL 路径（`/mnt/c/code/DeverDesk`） | 路径取最后一段即可 | 同上 |

实测（本机 git 2.55，Windows）：每次 git 调用约 33–58 毫秒，Node 启动约 76 毫秒，所以会话里第一次算出目录名后缓存起来，后面的钩子直接用。

副业有一个可选字段「目录名」，可以填多个，匹配时不分大小写。两个不同项目的文件夹同名会被当成一个，改文件夹名即可。

## 绑定与上传

- 本机记录放用户目录 `~/.deverdesk/`（按天分文件），所有目录都记，一直保留。不放项目目录：项目目录会被删、被重新克隆，工作树用完也会删。
- 只上传已绑定的目录名：记录器同步时从服务器取「已绑定的目录名」清单，清单外的一条都不出本机；服务器收到未绑定目录的数据也会拒收。
- 绑定由用户说了算：在那个目录里对 AI 说「把这个项目加进 DeverDesk」或「算到模板站里」，AI 用当前目录名新建副业或绑到已有副业（也可以在副业设置里手填「目录名」）；下次同步时，这个目录以前的记录一次补上。解绑：去掉目录名即可，已经上传的不会撤回。
- 没绑定也能问：AI 直接读本机记录回答「这周在 scraper 上花了多久」（`recorder status`）。
- 隐私：对话原文只留在本机，只用来给任务起名；上传的只有时间、目录名、提交说明和任务名。

## 精确规则

时间一律是毫秒时间戳（真实时间），本节的「分钟」只是文字说明。常量集中写在 `integrations/recorder/src/core/constants.ts`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `PRESENCE_GAP` | 15 分钟 | 相邻两次动静间隔小于它，中间都算你在场 |
| `AI_ALONE_CAP` | 15 分钟 | 你发话后 AI 自己干活，最多只算前 15 分钟 |
| `IDLE_ARRIVAL` | 2 小时 | 一个窗口这么久没动静，攒下的工作收成一个任务 |
| `BURST_GAP` | 2 分钟 | 相隔不到它的提交算「一口气连着提交」 |
| `MICRO_TASK` | 3 分钟 | 比它短的零碎提交，并进上一个任务 |
| `MERGE_WINDOW` | 2 小时 | 并进上一个任务的前提：上一个任务在这之内到站 |
| `MIN_ENTRY` | 0.5 分钟 | 比它短的时间段不记 |
| `SETTLE_LAG` | 30 秒 | 只算到「现在 − 30 秒」，避开刚写进日志还没落稳的事件 |

### 动静与在场

一个会话（窗口）里有这些动静，按时间排序：

| 动静 | 来源 | 算不算「你在场」的证据 |
| --- | --- | --- |
| 发话 `prompt` | UserPromptSubmit 钩子 | 算 |
| 干完一轮 `stop` | Stop 钩子 | 算 |
| 会话结束 `end` | SessionEnd 钩子 | 算 |
| 会话开始 `start` | SessionStart 钩子 | 不算（只记下目录和来源，提醒不了你在不在） |
| 提交 `commit` | 钩子里查 git，时间取提交自己的时间 | 不算（只是「到站」的标记） |
| 报告做完 `done` | AI 或你主动调用 | 不算（也是「到站」的标记） |

相邻的两个「算」的动静 a、b（按时间顺序）之间，a 之后的这一段是否计入你的时间：

- a 是发话：计入 `[a, a + min(b − a, AI_ALONE_CAP)]`（AI 干得久也最多算前 15 分钟）。
- a 是干完一轮：`b − a < PRESENCE_GAP` 时整段计入 `[a, b]`；不然这一段不算（你走开了）。
- a 是会话结束：不计入，下一个动静开启新的一段。
- 窗口里最后一个动静 a 后面还没有下一个：a 是发话时，计入 `[a, min(现在, a + AI_ALONE_CAP)]`（这部分是确定的，不会被将来的动静推翻）；a 是干完一轮或结束时，先不计入，等下一个动静出现再回头补。

不论有没有提交，没有「算」的动静的会话（只有 start）不产生时间。

### 并行平分

所有窗口（含没绑定的、不同项目的）一起算：任一时刻处于「计入」状态的窗口有 n 个，每个窗口分到这一刻的 1/n。所以各窗口分到的时间加起来不会超过真实流逝的时间。

算法：收集所有窗口计入段的端点，切成互不重叠的小段，每个小段里的在场窗口集合不变，窗口分到「小段长度 ÷ 窗口数」。窗口一连串相邻的小段合成一段（`run`）：真实起止是这一串的两端，计入分钟是各小段所得之和。

### 到站

「到站」是把一个窗口攒下的计入时间收成一个已完成任务。从上一次到站（窗口的第一次是它的第一个计入时刻）到这次到站时刻 T 之间的计入段，全归这个任务。到站的标记：

1. **提交**：时间取提交自己的时间。相隔不到 `BURST_GAP` 的连续提交算一批，一批共用一次到站（时刻取最后一个提交），攒下的时间按各提交改动行数（增加 + 删除，至少 1）分给每个提交，每个提交一个任务。
2. **报告做完**：任务名用报告的标题。
3. **会话结束**：攒下的时间 ≥ `MICRO_TASK` 时收成一个任务；不够就并进上一个任务（上一个任务在 `MERGE_WINDOW` 内）；没有上一个任务就丢掉。
4. **闲置**：窗口两个相邻的动静相隔 ≥ `IDLE_ARRIVAL`，或最后一个动静距现在 ≥ `IDLE_ARRIVAL`，在最后一个动静（或最后一个计入段的末尾，取较晚者）到站，规则同会话结束。

零碎提交：一次提交（含一批里分到的份额）计入时间 < `MICRO_TASK` 且上一个任务在 `MERGE_WINDOW` 内，不新建任务，提交挂到上一个任务的提交列表，时间段挂到上一个任务名下；没有上一个任务时，计入时间 ≥ 1 分钟的仍然新建任务，不到 1 分钟的丢掉（多半是你手动提交，和 AI 会话无关）。

### 任务

| 字段 | 取值 |
| --- | --- |
| 任务名 | 提交：去掉说明开头的 `feat:`、`fix(范围):` 这类前缀，最多 80 字。报告做完：报告的标题。会话结束或闲置：这一段里你的第一句话（第一个有内容的句子，最多 40 字，加省略号）；找不到就用「编程 HH:mm–HH:mm」 |
| 状态 | 已完成，完成时间是到站时刻 |
| 计划日、预估 | 都不填（预估记 0）：不占当天计划容量，也不进「估时准不准」的统计 |
| 副业 | 目录名绑定的副业 |
| 来源标记 | `origin: "coding"`，页面上带「自动记录」小图标 |
| 引用已有任务 | 提交说明的第一行，或以 `Closes` / `Fixes` / `Refs` / `Task` / `Done` / `完成` / `关闭` 开头的行里写了 `T-123`：不新建任务，把 T-123 标成完成（已经完成的不改完成时间），时间段记到它名下；T-123 不存在就当普通提交新建任务 |

任务名的提交说明里没有 `T-` 之外的信息时（例如 `wip`），照用原文。

### 时间段（投入记录）

一个任务的时间段 = 这一站内每个 `run` 一条：真实起止，计入分钟（并行时比真实时长短）。分钟取整数：先按小数算，再取整，保证一个任务各段之和等于总数四舍五入的结果（余数分给最长的一段），不足 `MIN_ENTRY` 的段不记。

### 边界

- 一个会话跨天：事件日志按事件自己的时间存，计算时不看天边界；任务和时间段带真实时间，页面按用户时区归到某天。
- 历史被改写（rebase、amend）：新提交的判断见 [本机记录器](本机记录器.md#提交怎么发现)，同一作者时间加同一说明的提交只算一次。
- 两台电脑同时在写：各算各的，不合并平分（罕见，不处理）。

## 页面上怎么显示

- 今天页「投入」列表：起止时间写真实的（并行时几行会重叠），右边分钟数是平分后分到的，加起来等于真实时间；还在做的窗口排在最上面，一个窗口一行「进行中」，和计时器那一行一个样子。
- 时间线左边加一条细的「实际」轨道，用副业颜色画真正在干活的时段，并行几个窗口就并排几根细条；自动记的任务不占当天计划容量，不会误报「排太满」。
- 任务看板和列表：自动记的任务直接在「已完成」里，卡片写用时。
- 副业页和概览：按平分后的时间算时薪。
- 详细规格见 [编程记录接口与显示](编程记录接口与显示.md)。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 按文件夹名认项目，不按仓库地址 | 有的项目不上传 git；工作树、子文件夹、WSL 路径都能认回同一个名字 |
| 本机记录放用户目录 | 项目目录会被删；不怕被误提交 |
| 只上传已绑定的目录 | 用户决定：用不用 DeverDesk 看板由用户说了算，没必要上传全部内容 |
| 一个窗口一块表，并行时平分 | 同一项目也会开几个窗口并行；总投入等于真实时间，时薪不被重复计时拉低 |
| AI 独自干活超过 15 分钟不算 | 用户定：副业时薪才准 |
| 用提交切任务 | 提交说明就是 AI 对「做完了一件事」的判断，确定、不花额度 |
| 钩子只追加事件，所有计算在 sync 里做 | 钩子每次都拖慢你发话和 AI 收尾，必须快（目标 100 毫秒内）；日志只追加，计算可以重来，结果可复现 |
| 不用 `CLAUDE_CODE_SESSION_ATTENDED` 判断有没有人在 | 实测通过 Agent SDK 宿主（如 codeg）有人在聊天时它也是 0；「AI 自己干活只算前 15 分钟」本身已经封顶了批量会话的误算 |
| 提议档令牌不能用来上传 | 上传要写数据，需要「直接改」档；记录器单独建一个令牌 |
| 上传走改动记录服务（批量模式） | 自动记的东西也能在 AI 动态里看到、整批撤销；批量模式不触发预览和限速，但每次上限 40 条改动 |
