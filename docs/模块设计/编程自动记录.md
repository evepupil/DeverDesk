# 编程自动记录

- 模块定位：用 AI 写代码时自动记工时和任务。本机记录器跟着 Claude Code、Codex 的会话记下「几点、在哪个项目、发生了什么」，按规则算出每件事用了多久；目录绑定了副业的，同步到 DeverDesk，变成已完成任务和投入时间。
- 对应代码：`integrations/recorder/`（本机记录器：规则引擎、本机存储、命令行）、`integrations/claude-code/`（Claude Code 插件）、`worker/recorder/`（服务器接口）、`src/features/projects/`（目录名设置）、`src/features/today/`（投入列表）
- 所属里程碑：[M6 编程自动记录](../roadmap.md#m6)
- 子文档：[本机记录器](本机记录器.md)（事件、存储、命令、钩子、回填）、[编程记录接入](编程记录接入.md)（Claude Code 插件、Codex、安装）、[编程记录接口与显示](编程记录接口与显示.md)（服务器接口、数据变化、页面）
- 当前状态：已完成（2026-10-02 用户验收通过）
- 最近更新：2026-10-02（评审后修订：在场、提交归属、键、取整、沉淀）

## 职责与边界

负责：认出会话属于哪个项目；记下会话里的动静；按规则把时间分到项目和任务；用提交切分任务；绑定后上传；没绑定的只留在本机。

不负责：手敲代码（没有 AI 会话）的计时；服务器上的任务、投入怎么存（沿用现有记录，见 [云端接口](云端接口.md)）。

## 一句话流程

```
Claude Code / Codex 的钩子 ──→ 本机记录器 ──→ ~/.deverdesk/ 里的事件日志（所有目录都记，永远留在本机）
                                    │
                         sync：从日志算出「到站的任务」
                                    │ 只挑已绑定副业的目录
                                    ▼
                         POST /api/recorder/upload ──→ 已完成任务 + 投入时间（带「自动记录」标记）
```

## 认项目：只看文件夹名

一条规则：

- 用了 git：问 git「这个仓库本体在哪」，取本体所在文件夹的名字；
- 没用 git：取会话所在文件夹的名字。

做法（`git rev-parse --path-format=absolute --git-common-dir`，注意这个开关要写在前面才生效）：

| 情形 | 判断 | 目录名 |
| --- | --- | --- |
| 普通仓库或它的子文件夹 | 公共目录是 `<仓库>/.git` | 仓库文件夹名 |
| 派活开的额外工作目录（worktree） | 公共目录指回主仓库的 `.git` | 主仓库文件夹名 |
| 子模块 | 公共目录在 `<上级>/.git/modules/…`，且 `--show-superproject-working-tree` 非空 | 子模块自己文件夹名（`--show-toplevel`） |
| 裸仓库（`foo.git`） | 公共目录不以 `.git` 结尾的文件夹名，或本身叫 `xxx.git` | 去掉 `.git` 后缀的名字 |
| 没用 git，或 git 不可用 | — | 会话所在文件夹名 |
| WSL 路径（`/mnt/c/code/DeverDesk`） | 路径取最后一段即可 | 同上 |

实测（本机 git 2.55，Windows）：每次 git 调用约 33–58 毫秒，Node 启动约 76 毫秒（经 Git Bash 间接启动约 125–148 毫秒），所以会话里第一次算出目录名后缓存起来，后面的钩子直接用。一个会话的目录名在它第一个事件时就定死（见「精确规则 · 窗口和目录名」）。

副业有一个可选字段「目录名」，可以填多个，匹配时不分大小写。两个不同项目的文件夹同名会被当成一个，改文件夹名即可。

## 绑定与上传

- 本机记录放用户目录 `~/.deverdesk/`（按天分文件），所有目录都记，一直保留。不放项目目录：项目目录会被删、被重新克隆，工作树用完也会删。
- 只上传已绑定的目录名：记录器同步时从服务器取「已绑定的目录名」清单，清单外的一条都不出本机；服务器收到未绑定目录的数据也会拒收。
- 绑定由用户说了算：在那个目录里对 AI 说「把这个项目加进 DeverDesk」或「算到模板站里」，AI 用当前目录名新建副业或绑到已有副业（也可以在副业设置里手填「目录名」）；下次同步时，这个目录以前的记录一次补上。解绑：去掉目录名即可，已经上传的不会撤回。
- 没绑定也能问：AI 直接读本机记录回答「这周在 scraper 上花了多久」（`recorder status`）。
- 隐私：对话原文只留在本机，只用来给任务起名；上传的只有时间、目录名、提交说明和任务名。本机事件日志里会留你每句话的第一句（最多 120 字），包括没绑定的目录；不想留，可以在 `config.json` 里设 `"privacy": { "promptText": false }`（或环境变量 `DEVERDESK_NO_PROMPT_TEXT=1`），没有提交的任务就只能用「Coding HH:mm–HH:mm」做名字。`config.json` 在 Windows 上没有文件权限保护，令牌更推荐放在 Claude Code 插件的安全存储里。

## 精确规则

时间一律是毫秒时间戳（真实时间），本节的「分钟」只是文字说明。常量集中写在 `integrations/recorder/src/core/constants.ts`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `PRESENCE_GAP` | 15 分钟 | 干完一轮后你在这么久之内回来，中间都算你在场 |
| `AI_ALONE_CAP` | 15 分钟 | 你发话后 AI 自己干活，最多只算前 15 分钟 |
| `IDLE_ARRIVAL` | 2 小时 | 一个窗口这么久没动静，攒下的工作收成一个任务 |
| `BURST_GAP` | 2 分钟 | 相隔不到它的提交算「一口气连着提交」 |
| `MICRO_TASK` | 3 分钟 | 比它短的零碎提交，并进上一个任务 |
| `MERGE_WINDOW` | 2 小时 | 并进上一个任务的前提：上一个任务在这之内到站 |
| `MIN_ENTRY` | 0.5 分钟 | 比它短的时间段不记 |
| `MIN_STANDALONE_TASK` | 1 分钟 | 没有可并入的任务时，计入时间不到它的零碎提交丢掉 |
| `SETTLE_DELAY` | `PRESENCE_GAP` + 30 秒 | 到站后至少过这么久才算数、才上传（见下面「沉淀」） |

### 窗口和目录名

- 提交事件不属于任何窗口（见「提交归属」），不参与窗口的目录名、在场、闲置判断；窗口只由 `start`、`prompt`、`stop`、`end`、`done` 这几种事件构成。
- 一个会话（窗口）有固定的会话编号；它的**目录名在它第一个（非提交）事件时就定死**，之后 AI 在会话里 `cd` 到子文件夹也不变（实测一个 8 小时的会话跨了 7 个当前目录；没用 git 的项目只有启动目录那个名字才是项目名）。实时记录取钩子环境里的 `CLAUDE_PROJECT_DIR`（会话启动时的项目根目录），没有就取第一个事件的 `cwd`；回填取会话文件里第一个 `cwd`。
- 引擎对同一个会话的所有事件一律用它第一个事件的目录名。

### 动静与在场

一个窗口里有这些动静，按（时间、种类顺序、原始顺序）排序，同一毫秒时种类顺序是：开始 `start` < 干完一轮 `stop` < 发话 `prompt` < 结束 `end`（例如排队的发话紧跟着上一轮收尾，先收尾后发话）：

| 动静 | 来源 | 算不算「你在场」的证据 |
| --- | --- | --- |
| 发话 `prompt` | UserPromptSubmit 钩子 | 算 |
| 干完一轮 `stop` | Stop 钩子 | 算 |
| 会话结束 `end` | SessionEnd 钩子 | 算（和 `stop` 同样对待，见下） |
| 会话开始 `start` | SessionStart 钩子 | 不算（只记下目录和来源） |
| 提交 `commit` | 钩子里查 git，时间取提交自己的时间 | 不算（「到站」的标记，归属见下） |
| 报告做完 `done` | AI 或你主动调用 | 不算（「到站」的标记） |

相邻的两个「算」的动静 a、b（按排序顺序）之间，a 之后的这一段是否计入你的时间：

- a 是发话：计入 `[a, a + min(b − a, AI_ALONE_CAP)]`（AI 干得久也最多算前 15 分钟）。
- a 是干完一轮或会话结束：**b 是你的发话或会话结束**且 `b − a < PRESENCE_GAP`（严格小于）时整段计入 `[a, b]`；其他情况不计入。b 也是干完一轮的（中间没有你的任何动静：后台任务通知唤醒 AI、定时循环）不计入——实测这类连接占总计入的 11%，不能算你的时间。
- 窗口最后一个动静 a 后面还没有下一个：a 是发话时计入 `[a, min(现在, a + AI_ALONE_CAP)]`（这部分是确定的，不会被将来的动静推翻）；否则先不计入，等下一个动静出现再回头补。

没有「算」的动静的窗口（只有 start）不产生时间。15 分钟是个悬崖（14 分 59 秒计入、15 分 0 秒不计入），这是你定的规则，不做平滑。

### 并行平分

所有窗口（含没绑定的、不同项目的）一起算：任一时刻处于「计入」状态的窗口有 n 个，每个窗口分到这一刻的 1/n。所以各窗口分到的时间加起来不会超过真实流逝的时间。

算法：收集所有窗口计入段的端点，切成互不重叠的小段，每个小段里的在场窗口集合不变，窗口分到「小段长度 ÷ 窗口数」。窗口一连串相邻的小段合成一段（`run`）：真实起止是这一串的两端，计入分钟是各小段所得之和。

### 沉淀：到站后等一等再算数

窗口 A 干完一轮后，你可能切到窗口 B 干了十分钟，再回到 A 发话——A 干完那一轮到你回来的这十分钟会**回头补**计入，并和 B 平分。所以一个时刻 x 上「谁在场」要等到 x + `PRESENCE_GAP` 之后才完全确定（需要的事件最迟出现在 x + 15 分钟内）。因此：

- 到站时刻为 T 的任务，要等到「现在 ≥ T + `SETTLE_DELAY`」才算数：引擎在这之前不输出它，同步也就不上传它。**没沉淀的到站标记整个当作还没发生**：它不会并进别的任务，也不会改变已输出任务的内容（先过滤到站标记，再生成任务）。
- 输出之后，这个任务的键、已输出的时间段和分钟都不会再变；之后只可能**追加**：零碎提交或会话结束并进它时，追加时间段和提交列表（它的完成时刻不顺延，避免零碎提交一环扣一环永远并下去）。
- 代价是任务在提交后约 15 分钟才出现在 DeverDesk 里；这段时间页面靠「进行中」显示（它是临时估算，不是最终数字）。为了不等到下一次钩子触发，发现新提交和会话结束时，记录器会在后台启动一个**延迟同步**（睡到该任务沉淀的时刻再同步一次，最多睡 20 分钟，之后自己退出，不是常驻进程）。
- 进行中的窗口（`open`）是临时估算，随新事件改变；它们不上传成任务。它攒的时间从**最后一个已沉淀的到站**算起（还没沉淀的那一站的时间在进行中里照样看得到，沉淀并上传之后再从进行中里扣掉）。

### 提交归属

提交事件（按「仓库 + 提交号」全局去重，与哪个窗口的钩子先发现无关）由引擎按**提交时刻谁在场**归属：

1. 目录名与该提交所在仓库的目录名相同（不分大小写）的窗口里，选「提交时刻 t 之前最后一个在场动静是发话」的（AI 正在这一轮里干活）；有多个选这个发话最晚的，再并列选会话编号小的。
2. 没有，就选「t 之前最后一个在场动静距 t 不到 `PRESENCE_GAP`」的（你刚看完结果、自己动手提交），同样选最晚的、再并列选会话编号小的。
3. 都没有：这是和 AI 会话无关的提交（手动提交、拉别的机器上的老提交），丢掉。

这样两个窗口同时在一个仓库里干活时，提交归给正在执行那一轮的窗口，而不是谁的钩子先发现。「之前」指严格早于提交时刻 t。

归属之后，**归给某个窗口的提交也算这个窗口的动静**（用在闲置判断里：窗口最后一个动静是它最后一个事件和最后一个归给它的提交中较晚的）。例如 AI 一个人跑了两小时没有任何收尾，期间做了提交，这个窗口不算闲置。

同一个提交可能被不同仓库路径发现两次（工作树合并回主仓库后再被发现）：引擎对提交再按「目录名（不分大小写）+ 提交号」去重。

**处理顺序**：提交按「max(提交时间, 发现时刻 `seenAt`)」排队处理，其他到站标记按自己的时间。晚发现的老提交（合并、rebase 带进来的）因此排在已经处理过的到站之后，它的区间 `T ≤ P` 为空，计入 0，只会追加到上一个任务的提交列表或被丢弃，不会重新切分已经输出的任务。没有 `seenAt` 的（回填）按提交时间排。

### 到站

「到站」是把一个窗口攒下的计入时间收成一个已完成任务。从该窗口上一次到站时刻 P（第一次是它第一个计入时刻）到这次到站时刻 T 之间的计入段，全归这个任务；`T ≤ P`（晚发现的老提交）时区间为空，计入 0，P 不回退。到站的标记：

1. **提交**：时间取提交自己的时间。相隔不到 `BURST_GAP` 的连续提交算一批，一批共用一次到站（时刻取最后一个提交），攒下的时间按各提交改动行数（增加 + 删除，至少 1）分给每个提交，**每个提交一个任务**（任务键用各自的提交号）。
2. **报告做完**：任务名用报告的标题；计入时间不够 `MICRO_TASK` 且上一个任务（`MERGE_WINDOW` 内）存在时并进上一个任务，否则新建（时间可以是 0）。
3. **会话结束**：只有结束之后同一会话 `PRESENCE_GAP` 内没有再出现在场动静时才到站（结束后马上续上的是同一次工作，不是离开）。攒下的时间 ≥ `MICRO_TASK` 时收成一个任务；不够就并进上一个任务（`MERGE_WINDOW` 内）；没有就丢掉。
4. **闲置**：窗口两个相邻的动静相隔 ≥ `IDLE_ARRIVAL`，或最后一个动静距现在 ≥ `IDLE_ARRIVAL`，在最后一个动静（或最后一个计入段的末尾，取较晚者）到站，规则同会话结束。

零碎提交：一次提交（含一批里分到的份额）计入时间（这一站所有时间段的精确分钟之和，丢弃不足 `MIN_ENTRY` 的段之前）< `MICRO_TASK`，且该窗口上一个任务在 `MERGE_WINDOW` 内：不新建任务，提交挂到上一个任务的提交列表，时间段挂到上一个任务名下。上一个任务在 `MERGE_WINDOW` 内包含正好等于 `MERGE_WINDOW` 的情形。没有可并入的上一个任务（不存在，或已超过 `MERGE_WINDOW`）时，计入时间 ≥ `MIN_STANDALONE_TASK` 的仍然新建任务，不到的丢掉。**例外**：提交说明里带了任务编号（`taskSeq`）的提交永远独立成一个任务条目上传（时间可以是 0），保证对应任务被标成完成。

### 任务

| 字段 | 取值 |
| --- | --- |
| 任务名 | 提交：去掉说明开头的 `feat:`、`fix(范围):` 这类前缀（只认 feat / fix / docs / refactor / test / chore / perf / style / build / ci / revert，半角 `:` 和全角 `：` 都认），最多 80 字。报告做完：报告的标题。会话结束或闲置：这一段里你的第一句话（第一个有内容的句子，最多 40 字，加省略号；句号只有后面跟空白或到结尾才算一句结束，所以 `fix foo.ts crash` 不会被切开）；找不到就用英文占位「Coding HH:mm–HH:mm」，时间是**这个任务第一个时间段的开始到最后一个时间段的结束**，按调用方给的本地时间格式化函数输出（引擎本身不管时区；没给就用 UTC） |
| 状态 | 已完成，完成时间是到站时刻 |
| 计划日、预估 | 都不填（预估记 0）：不占当天计划容量，也不进「估时准不准」的统计 |
| 副业 | 目录名绑定的副业 |
| 来源标记 | `origin: "coding"`，页面上带「自动记录」标记 |
| 引用已有任务 | 提交说明的第一行，或以 `Closes` / `Fixes` / `Refs` / `Task` / `Done` / `完成` / `关闭` 开头（行首可以有空白，关键字和 `T-` 之间空白、冒号、全角冒号都可以没有，如 `完成T-8`、`完成了 T-8`）的行里写了 `T-123`（数字 1 到 6 位，更长的不算）：不新建任务，把 T-123 标成完成（已经完成的不改完成时间），时间段记到它名下；T-123 不存在就当普通提交新建任务 |

任务名的提交说明里没有 `T-` 之外的信息时（例如 `wip`），照用原文。

### 时间段（投入记录）与取整

一个任务的时间段 = 这一站内每个 `run` 一条：真实起止，计入分钟（并行时比真实时长短）。分钟取整规则（确定、可复现）：

1. 每段先算精确分钟（可以是小数；**用整数毫秒累加，比较和进位时留 1e-9 的误差余量**，免得整半分钟被浮点误差算错）；不足 `MIN_ENTRY` 的段先丢掉；
2. 任务总分钟 N = 四舍五入（0.5 进位）的剩余各段精确分钟之和；
3. 把 N 按**最大余数法**分给各段：每段先取整数部分，剩下的整数分钟依次分给小数部分最大的段，小数部分相同时先给开始时间早的段；
4. 分到 0 分钟的段丢掉。

所以一个任务各段整数之和等于 N；每个保留的段至少 1 分钟。

### 键

任务和时间段的键必须稳定（重算不变），也不能撞：

| 对象 | 键 |
| --- | --- |
| 任务 | `<agent>:<会话>:<标记编号>`，标记编号：提交 `c:<提交号>`、报告做完 `d:<时刻毫秒>`、会话结束 `e:<时刻毫秒>`、闲置 `i:<时刻毫秒>` |
| 时间段 | `<任务键>#<段开始毫秒>#<来源标记编号>`；任务自己攒下的时间段，来源标记编号就是它自己的；并进它的零碎提交、会话结束的时间段，来源标记编号是那个被并入的标记，所以不会和自己的撞键 |

### 边界

- 一个会话跨天：事件日志按事件自己的时间存，计算时不看天边界；任务和时间段带真实时间，页面按用户时区归到某天。
- 一个会话被恢复（resume）：会话编号不变，照常按时间排；前后相隔很久由闲置规则处理。
- 历史被改写（rebase、amend）：新提交的判断见 [本机记录器](本机记录器.md#提交怎么发现)，同一作者时间加同一说明的提交只算一次。
- 两台电脑同时在写：各算各的，不合并平分（罕见，不处理）。
- 事件顺序和时钟：时间倒退的事件（回填的会话记录里实测有）一律按时间排序后再算。
- 去重：内容不同但键相同的重复事件，保留内容（序列化后）字典序最小的那一条，保证结果和输入顺序无关。
- 缺必填字段的事件（时间不是有限数、缺 `kind`/`session`/`agent`、非提交事件缺 `dir`、提交缺 `repo`/`sha`/`subject`）整条丢弃，不报错；提交的改动行数不是有限数当 0。
- 同一时刻多个到站：按 提交 < 报告做完 < 会话结束 < 闲置 的顺序处理；同一毫秒的多个提交按（仓库，提交号）排。

## 页面上怎么显示

- 今天页「投入」列表：起止时间写真实的（并行时几行会重叠），右边分钟数是平分后分到的，加起来等于真实时间；还在做的窗口排在最上面，一个窗口一行「进行中」，和计时器那一行一个样子。
- 时间线左边加一条细的「实际」轨道，用副业颜色画真正在干活的时段，并行几个窗口就并排几根细条；自动记的任务不占当天计划容量，不会误报「排太满」。
- 任务看板和列表：自动记的任务直接在「已完成」里，卡片写用时。
- 副业页和概览：按平分后的时间算时薪。
- 详细规格见 [编程记录接口与显示](编程记录接口与显示.md)。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 按文件夹名认项目，不按仓库地址 | 有的项目不上传 git；工作树、子文件夹、WSL 路径都能认回同一个名字 |
| 本机记录放用户目录 | 项目目录会被删；不怕被误提交 |
| 只上传已绑定的目录 | 用户决定：用不用 DeverDesk 看板由用户说了算，没必要上传全部内容 |
| 一个窗口一块表，并行时平分 | 同一项目也会开几个窗口并行；总投入等于真实时间，时薪不被重复计时拉低 |
| AI 独自干活超过 15 分钟不算 | 用户定：副业时薪才准 |
| 用提交切任务 | 提交说明就是 AI 对「做完了一件事」的判断，确定、不花额度 |
| 钩子只追加事件，所有计算在 sync 里做 | 钩子每次都拖慢你发话和 AI 收尾，必须快（目标 100 毫秒内）；日志只追加，计算可以重来，结果可复现 |
| 干完一轮到下一次干完一轮不算在场 | 评审用本机 191 个真实会话回放：后台任务通知唤醒 AI、定时循环这类「没有你参与」的连接占总计入的 11%，不能算你的时间 |
| 提交归属由引擎按提交时刻谁在场决定 | 并行窗口同一个仓库时，谁的钩子先发现提交是随机的；按谁在场归属才确定 |
| 目录名在窗口第一个事件时定死 | 实测 185 个会话里 74 个的当前目录中途变过，一个没用 git 的项目在一个会话里变了 7 个名字，取最后一个会让整段时间永远传不上去 |
| 不用 `CLAUDE_CODE_SESSION_ATTENDED` 判断有没有人在 | 实测通过 Agent SDK 宿主（如 codeg）有人在聊天时它也是 0；「AI 自己干活只算前 15 分钟」本身已经封顶了批量会话的误算 |
| 提议档令牌不能用来上传 | 上传要写数据，需要「直接改」档；记录器单独建一个令牌 |
| 上传走改动记录服务（批量模式） | 自动记的东西也能在 AI 动态里看到、整批撤销；批量模式不触发预览和限速，但每次上限 30 条改动 |

## 当前实现

已实现，见三份模块文档里的「当前实现」：[本机记录器](本机记录器.md#当前实现)（引擎、钩子、同步）、[编程记录接入](编程记录接入.md#当前实现)（Claude Code 插件、Codex 钩子）、[编程记录接口与显示](编程记录接口与显示.md#当前实现)（服务器接口、页面）。上面「精确规则」一节就是引擎的行为说明，引擎的单测、性质测试和差分测试都按它写。

规则上线时的几点与最初设计的差别：评审用 191 个真实会话回放后，「在场」不再用 `SessionAttended` 判断、提交归属改由引擎按提交时刻谁在场决定、增加了「沉淀」等待；提交一律由引擎按「窗口的动静」归属，窗口自己的目录名在第一个事件时定死。

## 验证方式

- 引擎：单测、性质测试、独立参考实现的差分测试（9,988 次比对没有不一致）；本机真实会话（只读）的回填结果与独立重数完全一致。
- 全链路：`pnpm e2e:recorder`（真实 `claude -p` 加载插件 → 事件 → 同步 → 任务和时间出现在本机 Worker → 重复同步不重复 → 未绑定目录一条不传 → 并行平分 → AI 动态里整批撤销 → 简报列出待完成的里程碑）53 项全过。
- 页面：`scripts/acceptance/m6-shots.mjs` 在真实浏览器里核对 37 项（目录名、投入列表、进行中行、实际轨道、连接 AI 的记录器分段、英文界面、失败和过期）并截图。
- 需要在用户机器上验收：codeg 宿主里钩子是否触发、Codex 实连、真实使用几天后的数字是否合理。
