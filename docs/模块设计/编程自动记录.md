# 编程自动记录

- 模块定位：用 AI 写代码时自动记工时和任务。本机记录器跟着 Claude Code、Codex 的会话记下「几点、在哪个项目、发生了什么」，按规则算出每件事用了多久；目录绑定了副业的，同步到 DeverDesk，变成已完成任务和投入时间。
- 对应代码：（未开始）计划为 `integrations/recorder/`（本机记录器）、`integrations/claude-code/`（Claude Code 插件：钩子、连接配置、技能）、Worker 新增上传接口
- 所属里程碑：[M6 编程自动记录](../roadmap.md#m6)
- 当前状态：未开始（设计已和用户定稿）
- 最近更新：2026-10-01

## 职责与边界

负责：认出会话属于哪个项目；记下会话里的动静；按规则把时间分到项目和任务；用提交切分任务；绑定后上传；没绑定的只留在本机。

不负责：手敲代码（没有 AI 会话）的计时；服务器上的任务、投入怎么存（沿用现有记录）。

## 认项目：只看文件夹名

一条规则：

- 用了 git：问 git「这个仓库本体在哪」（`git rev-parse --git-common-dir`，工作树也指回主仓库），取本体所在文件夹的名字；
- 没用 git：取当前文件夹的名字。

| 会话在哪开 | 记成 |
| --- | --- |
| `C:\code\DeverDesk` | DeverDesk |
| `C:\code\DeverDesk\site`（子文件夹） | DeverDesk |
| `C:\code\DeverDesk\.claude\worktrees\a`（派活开的工作树） | DeverDesk |
| `/mnt/c/code/DeverDesk`（WSL） | DeverDesk |
| `C:\code\scraper`（没用 git） | scraper |

副业多一个可选字段「目录名」，可以填多个，不分大小写。两个不同项目的文件夹同名会被当成一个，改文件夹名即可。

## 绑定与上传

- 本机记录放用户目录 `~/.deverdesk/`（按天分文件），所有目录都记，一直保留（一年十来 MB）。不放项目目录：项目目录会被删、被重新克隆，工作树用完也会删。
- 只上传已绑定的目录名：记录器定期从服务器取「已绑定的目录名」清单，清单外的一条都不出本机。
- 绑定由用户说了算：在那个目录里对 AI 说「把这个项目加进 DeverDesk」或「算到模板站里」，AI 用当前目录名新建副业或绑到已有副业；下次同步时，这个目录以前的记录一次补上。解绑：「这个目录别再同步了」。
- 没绑定也能问：AI 直接读本机记录回答「这周在 scraper 上花了多久」。
- 隐私：对话原文只留在本机，只用来给任务起名；上传的只有时间、目录名、提交说明和任务名。

## 计时：像出租车打表

- 一个窗口（会话）一块表。动静有三种：你发话、AI 干完一轮、有了新提交。
- 相邻两次动静间隔不到 15 分钟，表一直走；超过 15 分钟没动静，表停。
- AI 一轮连续干很久、你一直没出声，只算你发话后的前 15 分钟（用户定：AI 自己干活的时间不算你的）。
- 同时开几个窗口：同一分钟有几块表在走，这一分钟就由这几个窗口平分，加起来等于真实时间。
- 后台没人看着跑的 AI 会话（批量派出去的）不算你的时间，它做完的活照样记成任务。
- 时间一产生就算进对应副业，页面上「今天投入」随时在涨。

## 任务：做完再记

- **提交就是到站**：每次提交，把这块表从上次到站到现在的时间归到一个新的已完成任务，任务名用提交说明（去掉开头的 feat: 这类标记）。AI 写提交说明的那一刻就是它判断「这件事做完了」的时候，不用另外教它、不多花额度。
- 怎么知道有新提交：AI 每干完一轮，记录器看一眼 git，手动提交的也认。
- 一口气连提几个：按各自改动的行数分时间；只花一两分钟的零碎提交并进上一个任务。
- 提交说明里带任务编号（T-123）：直接把那个已有任务标成完成，不新建。为此会话开始时把这个副业没做完的任务和编号告诉 AI。
- 没有提交的活：AI 报告做完（调本机记录器的「记完成」，断网也能记）、关窗口、或者两小时没动静，都算到站；这种任务的名字由便宜的小模型读这段对话起，起不出来用第一句话截短。
- AI 干活时发现了但没做的事（比如顺手看到的 bug），进这个副业的想法列表。
- 自动记的任务带标记；记错了在页面上改名、合并、换副业，或在 AI 动态里撤销。

例：

| 时间 | 发生了什么 | 结果 |
| --- | --- | --- |
| 10:00 | 你发话「给支付回调加重试」 | |
| 10:14 | AI 干完一轮 | |
| 10:20 | 你发话「再补个单测」 | |
| 10:31 | 新提交「feat: 支付回调失败自动重试」 | 已完成任务「支付回调失败自动重试」，31 分钟 |
| 10:31–11:41 | 70 分钟没动静 | 不算 |
| 11:41–12:05 | 你发话、AI 排查、关窗口，没有提交 | 已完成任务「排查构建变慢」，24 分钟（小模型起名） |

## 页面上怎么显示

- 今天页「投入」列表：起止时间写真实的（并行时几行会重叠），右边分钟数是平分后分到的，加起来等于真实时间；还在做的窗口排在最上面，一个窗口一行「进行中」，和计时器那一行一个样子。
- 时间线左边加一条细的「实际」轨道，用副业颜色画真正在干活的时段，并行几个窗口就并排几根细条；自动记的任务不占当天计划容量，不会误报「排太满」。
- 任务看板和列表：自动记的任务直接在「已完成」里，卡片写用时。
- 副业页和概览：按平分后的时间算时薪。

## 接入方式

- Claude Code：做成插件，装上就带连接配置、钩子（Claude Code 在会话开始、你发话、它干完一轮时自动跑的小程序）和「记完成」工具。
- Codex：用它的每轮结束通知接进来。
- 装上时把最近 30 天的会话补回来：Claude Code 默认把最近 30 天的对话存在本机，Codex 也有会话记录，每句话都带时间。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| 按文件夹名认项目，不按仓库地址 | 有的项目不上传 git；工作树、子文件夹、WSL 路径都能认回同一个名字 |
| 本机记录放用户目录 | 项目目录会被删；不怕被误提交 |
| 只上传已绑定的目录 | 用户决定：用不用 DeverDesk 看板由用户说了算，没必要上传全部内容 |
| 一个窗口一块表，并行时平分 | 同一项目也会开几个窗口并行；总投入等于真实时间，时薪不被重复计时拉低 |
| AI 独自干活超过 15 分钟不算 | 用户定：副业时薪才准 |
| 用提交切任务 | 提交说明就是 AI 对「做完了一件事」的判断，确定、不花额度 |
