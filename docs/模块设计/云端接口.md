# 云端接口

- 模块定位：在线版的服务器端。一个 Cloudflare Worker（Cloudflare 上跑的服务端程序）同时提供打包好的页面和 `/api` 接口，数据存在 D1（Cloudflare 的 SQLite 数据库）。
- 对应代码：`worker/`（`index.ts` 入口、`routes/` 各接口、`auth/` 身份校验、`db/` 数据库读写、`validation.ts` 请求内容校验、`migrations/` 建表语句）、`wrangler.jsonc`；前后端共用的约定在 `src/sync/protocol.ts`
- 所属里程碑：[M2 在线版后端](../roadmap.md#m2)；令牌权限、改动记录接口、`/mcp` 入口属于 [M4](../roadmap.md#m4)
- 当前状态：已完成（M2、M4 均已验收）
- 最近更新：2026-10-02

## 职责与边界

负责：分发页面文件；校验每个接口请求是谁发的；存取同步记录并裁决冲突；管理个人令牌和它的权限；操作接口（建任务、记一笔、月度汇总）；把 `/mcp` 交给 [MCP 服务](MCP服务.md)；给页面用的 AI 改动接口（规则见 [AI 改动记录](AI改动记录.md)）。
不负责：浏览器里的离线队列和合并（见 [同步](同步.md)）、登录界面（见 [登录与令牌](登录与令牌.md)）、MCP 协议和各个工具（见 [MCP 服务](MCP服务.md)）。

## 结构与数据流

```
浏览器 / AI 客户端 ──→ Worker 入口
            ├─ /mcp ────→ MCP 服务（只认访问令牌）──────────────→ D1
            ├─ /api/* ──→ 路由表 ──→ 身份校验 ──→ 各接口 ──→ D1
            │                 ①          ②           ③
            └─ 其它路径 ──→ 静态页面（out/），找不到给 404 页
```

1. 路由表只认下表里的接口，别的一律 404。
2. 身份校验按顺序认三种：Cloudflare Access（Cloudflare 的登录网关）→ 个人令牌 → 口令登录后的 Cookie。都不认就 401；口令和 Access 都没配置时 503，提示还没有设置口令。个人令牌带权限档（只看 / 只能提议 / 直接改），按下表限制能用的接口。
3. 每个接口自己校验请求内容，出错给一句中文原因。

| 接口 | 做什么 | 谁能用 |
| --- | --- | --- |
| `GET /api/session` | 查是否已登录、是否开了口令登录 | 任何人 |
| `POST /api/session` | 口令登录，成功发 30 天的会话 Cookie | 任何人（有失败限速） |
| `DELETE /api/session` | 退出登录，清掉 Cookie | 任何人 |
| `GET /api/sync?since=&limit=` | 从某个写入顺序号往后拉记录，每页最多 500 条 | 已登录（任何权限的令牌都行） |
| `POST /api/sync` | 上传改动，每批最多 40 条；返回被云端更新版本压下的那些记录 | 口令、Access，或「直接改」令牌 |
| `GET` / `POST /api/tokens`、`PATCH` / `DELETE /api/tokens/<编号>` | 列出、新建（带名称和权限）、改权限、撤销个人令牌 | 口令或 Access 登录（个人令牌不能管理令牌） |
| `POST /api/tasks` | 建任务，显示编号接着最大的往后排；经改动记录写入，能在 AI 动态里撤销 | 口令、Access，或「直接改」令牌 |
| `POST /api/ledger` | 记一笔收支；同上经改动记录写入 | 口令、Access，或「直接改」令牌 |
| `GET /api/summary?month=YYYY-MM` | 当月收入、支出、净利润、投入分钟数、完成任务数；默认月份按用户时区 | 已登录 |
| `GET /api/ai/changesets`、`POST /api/ai/changesets/<编号>/accept\|reject\|undo` | 列出 AI 改动包、采纳、拒绝、撤销（见 [AI 改动记录](AI改动记录.md)） | 口令或 Access 登录（个人令牌一律 403） |

数据库六张表：

| 表 | 存什么 |
| --- | --- |
| `records` | 每条记录一行：种类 + 编号做主键，内容（JSON，删除后为空）、修改时间、写入顺序号、是否删除、来源（页面 / 接口） |
| `tokens` | 个人令牌：名称、令牌的摘要（不存明文）、权限档、创建时间、最近使用时间 |
| `login_failures` | 按 IP 记的登录失败次数和计数起点 |
| `settings` | 服务器端设置：会话签名用的随机密钥、改动记录上次清理时间 |
| `ai_changesets`、`ai_changes` | AI 改动包和每条改动的改前改后（见 [AI 改动记录](AI改动记录.md)） |

迁移 0003（`worker/migrations/0003_ai.sql`）：令牌表加权限档（老令牌按「直接改」，保持原来的能力）；建两张改动记录表；给 `records` 加按 JSON 字段的表达式索引（只覆盖没删除的记录）：投入的开始时间、收支的日期和外部单号、任务的状态、计划日、完成时间。

## 关键决策

| 决策 | 理由 |
| --- | --- |
| Worker 同时托管页面和接口，不用 Pages | 一个部署单元、一个域名；Cloudflare 的一键部署按钮只支持 Worker |
| 每条记录一行（任务、收支、投入记录、例行……），带修改时间和写入顺序号 | 两台设备改不同的记录互不影响；拉取只拿上次之后写入的，不用每次整份下载 |
| 冲突按修改时间，新的赢，时间相同以后到的为准 | 个人使用，两台设备同时改同一条很少见；规则简单，结果可以预期 |
| 删除留一条内容为空的记录 | 别的设备拉取时才知道这条被删了 |
| 一批改动用 D1 的批量执行写入 | 一批要么全写进、要么全不写；40 条一批加上身份校验和回查，一次请求约 43 次查询，低于免费版单次 50 次的上限 |
| 写入顺序号用「当前最大值 + 1」 | D1 对同一个库的写入逐条排队执行，不会并发拿到同一个号 |
| 会话 Cookie 的签名密钥由服务器端随机密钥和口令一起算出 | 随机密钥首次用到时生成、只存在数据库里，别人照着开源代码也拼不出能用的 Cookie，猜口令只能走有限速的登录接口；改口令会让所有设备下线 |
| 登录失败限速：同一 IP 15 分钟内 10 次 | 口令是唯一的门，防止暴力猜 |
| 个人令牌只存摘要，明文只在新建时返回一次 | 数据库内容泄露也拿不到能用的令牌 |
| Access 登录：优先认 Cloudflare 传进来的身份；也自己校验 Access 令牌的签名、签发方、受众、过期和生效时间（允许 60 秒误差） | 部署在 Access 后面时不用再输口令；自己校验防止伪造请求头 |
| Access 公钥缓存 15 分钟；遇到没见过的钥匙编号时强制刷新，最多每分钟一次 | Access 换钥后最多晚一分钟认新钥；随便编的钥匙编号不能让每个请求都去拉一次公钥 |
| 修改时间只要求是非负整数毫秒，不设上限 | 浏览器打时间戳取「现在」和「这条已知的最新时间 + 1」中较大的，带着超前时间的记录照样能被后面的修改盖过；服务器要是拒收超前的时间，时钟不准的设备就再也传不上去 |
| 操作接口写入的记录来源标成「接口」 | 以后能区分 AI 助手改的和人改的 |
| 令牌分三档权限，老令牌按「直接改」 | 新建默认「只能提议」更稳妥；老令牌保持原来能建任务、记账的能力，不让已经接好的脚本突然失效 |
| 只有「直接改」令牌能上传同步改动 | 否则只看或只能提议的令牌绕过 MCP，直接从同步接口改数据 |
| 操作接口改走改动记录 | 令牌写入的东西都能在页面里看到和撤销，不分走的是 MCP 还是老接口 |
| 月度汇总按日期只查当月记录 | 一次读出全部历史在免费版的 CPU 上限内放不下（见 [调研](../调研/MCP协议与SDK.md)） |

## 当前实现

- 口令从部署时设的机密变量 `DEVERDESK_PASSWORD` 读取；Access 需要再设 `ACCESS_TEAM_DOMAIN` 和 `ACCESS_AUD` 两个变量，不设就只用口令。
- 会话 Cookie：`HttpOnly`、`Secure`、`SameSite=Strict`，有效期 30 天。
- 个人令牌形如 `dd_` 加 43 位随机字符，请求时放在 `Authorization: Bearer` 头里；每分钟最多更新一次「最近使用时间」。
- 建任务接口在一条语句里算出下一个显示编号并写入，不会和云端已有的任务重号。
- 月度汇总在 Worker 里直接调用页面用的计算函数（`src/domain/` 的收支合计、投入时长、完成数），结果和概览页一致；只查当月的收支、投入和完成的任务（查询走 0003 的表达式索引），默认月份和月界按作息设置里的时区。
- 令牌带权限档：新建时可选（不选为「只能提议」），`PATCH /api/tokens/<编号>` 改权限；只看和只能提议的令牌上传同步、调 `/api/tasks`、`/api/ledger` 都回 403；任何令牌调 AI 改动接口都回 403。
- 建任务、记账两个老接口经改动记录服务写入（工具名 `rest:tasks`、`rest:ledger`），能在 AI 动态里看到和撤销；口令或 Access 登录调用时记成「DeverDesk」。
- `/mcp` 在 Worker 入口分流（`wrangler.jsonc` 的 `run_worker_first` 加了 `/mcp`；自己部署的配置副本也要加，否则 `/mcp` 会被静态页面接走）。
- 出错一律返回 `{ error: 一句话 }`；限速时多带 `retryAfter`（还要等几秒）。

## 验证方式

- `pnpm typecheck`：含 `worker/` 的类型检查。
- `pnpm test`：`worker/**/*.test.ts` 覆盖会话令牌、Access 令牌、同步请求内容校验。
- `pnpm build && pnpm e2e`：本机起 `wrangler dev`（独立的临时数据库），两个浏览器上下文模拟两台设备，核对登录、互相同步、离线补传、同时修改、访问令牌建任务、断网时退出被拦下、退出登录，共 14 项；M4 加了 10 项（三档令牌、`/mcp` 鉴权、新老协议、时区、AI 建任务和标记、提议采纳、撤销、删除预览、权限边界、输入出错），共 24 项。
- `worker/testing/d1-sqlite.mjs`：用 Node 自带的 SQLite 跑真实的建表语句，数据库相关的单测都用它。
