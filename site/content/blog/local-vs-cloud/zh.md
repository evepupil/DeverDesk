选择一个工作工具时，最该先弄清楚的事情之一，是记录最后存在哪里。DeverDesk 有本地版和在线版：两者来自同一套代码，打包时选定使用哪一种。页面看起来相近，保存和同步方式则不同。

本地版适合想打开就用、数据留在当前浏览器的人。在线版适合希望多设备使用，并愿意把服务部署到自己 Cloudflare 账号的人。先看下面的数据流，再决定哪种更适合你的习惯。

## 本地版：记录只在这个浏览器

本地版把数据保存在当前浏览器。打开 [app.deverdesk.com](https://app.deverdesk.com) 时，看到的是带样例数据的本地版；你的新增和修改都留在本机浏览器里，不会发送到服务端。它无需在线账户，也没有跨设备同步。

浏览器数据被清除后，本地保存的工作记录也会消失，所以定期导出备份很重要。头像菜单里的「导出备份」可以把记录保存成文件；需要迁移到另一处时，再通过导入备份恢复。演示站选择本地版，正是因为它作为静态应用运行，不需要服务端替每个访客保存数据。

## 在线版：自己的 D1 加本机缓存

在线版部署在你自己的 Cloudflare 账号中，持久记录保存在 D1 数据库。D1 是 Cloudflare 提供的 SQLite 数据库。浏览器仍保留本机缓存和待上传队列，所以进入工作台后可以先读本机数据，改动也会先保存到本机，然后再由同步引擎处理。

同步按记录进行：本机把改过的记录排队上传，再拉取其他设备的新记录。断网时照常使用，队列会留在浏览器里；恢复联网后自动补传。同步状态图标会显示已同步、正在同步、离线或出错等状态。每台设备上的语言偏好各自保存在本机，数据内容则按在线版规则同步。

## 两台设备改了同一条记录

同步会把独立记录分别合并，所以一台设备新增任务、另一台设备记下收入时，两项改动可以都保留下来。若两台设备都修改同一条记录，系统比较这条记录的修改时间，较新的版本成为当前记录；其他没有冲突的记录仍按条合并。同步文档还说明，设备时钟稍慢时会把新修改的时间推进到已知版本之后，避免本机改动被误认成旧版本。

实际使用时，联网状态和窗口栏同步提示能帮助你确认队列是否已补传。退出登录会清掉本机缓存；如果还有改动未上传，DeverDesk 会先要求确认。离线退出不会清理成功，因此要等联网后再退出。

## 一眼比较，再按习惯选择

| 对比项 | 本地版 | 在线版 |
| --- | --- | --- |
| 数据存在哪 | 当前浏览器 | 你自己的 Cloudflare D1；浏览器另有工作缓存 |
| 多设备同步 | 不提供 | 自动按记录同步，断网后联网补传 |
| 登录 | 不需要 | 访问口令或 Cloudflare Access |
| 怎么获得 | 打开 app.deverdesk.com | 从仓库一键部署或手动部署 |

想立刻试用、避免登录流程，可以先开演示站，并按时导出备份。需要两台设备查看同一份数据，就部署在线版，再用备份导入把本地记录带过去。两种版本的步骤见[Cloudflare 部署指南](/zh/blog/deploy-to-cloudflare/)。DeverDesk 采用 AGPL-3.0 开源；查看源代码可以从[产品仓库](https://github.com/evepupil/DeverDesk)开始。

选版本时，不必先猜一种抽象的「云端更方便」或「本地更私密」。问自己：我是否需要多设备共享同一份记录？我愿不愿意管理自己的 Cloudflare 部署？备份是否已经安排进日常习惯？答案会比版本名字更有用。

## 换设备时要带走什么

本地版的数据属于当前浏览器，不会因为在另一台电脑打开同一个网址就自动出现。换设备之前，从原浏览器导出备份，再在目标环境导入。在线版则由自己的 D1 保存记录，新设备登录后可以从云端拉取已有数据；第一次登录的新设备会从空白数据开始拉取，不会把空白内容覆盖到云端。

在线版每台设备都会保留缓存和待上传队列。离线时记录先留在本机，连接恢复后上传；如果你准备退出登录，先留意同步状态，确保没有尚未上传的改动。退出登录会清除这台设备上的在线缓存，因此提示有待上传时应先确认改动是否可以放弃。
