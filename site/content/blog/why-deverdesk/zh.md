独立开发者的一天，很少只围着一个项目转。白天处理工作，晚上可能更新模板商城，检查接口中转的状态，写一篇技术博客，再回几封付费咨询邮件。每件事都不大，放在一起却像一间没有办公室、没有同事、也没有运营助理的小公司。

问题在于，这些工作留下的信息分散在不同地方：任务清单知道你答应了什么，日历记得你什么时候忙过，收支表里躺着到账和支出。想回答一个实际的问题时，线索很难拼起来：我在模板商城花掉的晚上，最后换来了多少收入？接口中转看起来收入不错，维护它又占去多少时间？

## 任务和钱分开时，很难作判断

只看任务完成数，会把忙碌误当成进展；只看到账金额，又看不到维持收入付出的时间。模板商城这个月到账不少，可能也花了许多晚上制作和答疑。博客直接收入有限，却可能是你愿意长期写作的渠道。单独看一张任务表或一份账本，都缺少另一半背景。

DeverDesk 的出发点很具体：把每项任务、每段投入时间和每笔收支都归到一个副业下面。记录有了共同的归属，系统就能把该副业的已到账净收入、投入小时和时薪放在一起看。你可以继续做自己的判断，至少不必先手工拼三份记录。

## 一张控制台里有什么

DeverDesk 有八个页面，各自处理一类日常工作：

| 页面 | 主要用途 |
| --- | --- |
| 今天 | 安排今日任务、时间线和例行事项，也查看今天的投入与本月净收入目标 |
| 本周 | 浏览七天容量，在不同日期间移动任务 |
| 任务 | 用看板或列表整理任务，并按状态、副业或优先级筛选 |
| 副业 | 按阶段看项目，比较净收入、投入、时薪、月目标和里程碑 |
| 收支 | 记录收入和支出，单独查看待到账项目，也可导出 CSV |
| 概览 | 把净收入、投入时间、时薪和完成任务放到趋势及副业拆分里 |
| 回顾 | 汇总一周完成的事、时间去向，并留下复盘笔记 |
| 例行 | 管理按天、周、月重复的事项和打卡记录 |

一笔收入归到哪个副业，一段时间花在哪个任务，取决于你记录时的选择。DeverDesk 提供整理和计算的视图，不会替你决定一个项目应不应该继续。时薪适合拿来发现差异、提出问题，不适合独自替代所有长期判断。

## 为什么开源，也为什么自己部署

DeverDesk 以 AGPL-3.0 开源。你可以检查、修改和自行部署；如果把修改版作为网络服务提供给别人，也需要向使用者公开相应源代码。公开源代码让产品的运行方式可以被检查，也让有需要的人能从现有代码出发调整自己的工作台。

在线版部署在你自己的 Cloudflare 账号里：静态页面和接口一起作为一个 Worker 发布，数据放在该账号的 D1 数据库。Worker 是 Cloudflare 上运行接口程序的服务，D1 是 Cloudflare 提供的 SQLite 数据库。财务数据由你自己的部署保存，不经过 DeverDesk 替你托管的账户。Cloudflare 免费额度对一个人使用绰绰有余，具体部署步骤见[在线版指南](/zh/blog/deploy-to-cloudflare/)和[仓库说明](https://github.com/evepupil/DeverDesk/blob/main/README.zh-CN.md)。

## 从一条记录开始

你可以先打开[在线演示](https://app.deverdesk.com)看看页面；它运行本地版和样例数据，改动留在当前浏览器。想先弄清两种版本的数据位置，可以读[本地版和在线版对比](/zh/blog/local-vs-cloud/)。开始使用时，挑一个副业，给它记下一项任务、一次投入和一笔收入。做过一段时间，再去概览页按副业查看数字，看看哪些地方值得继续追问。

DeverDesk 希望帮助一个人更清楚地看见已经发生的工作：把时间、任务与收支放回各自的项目，让安排晚上的时间时多一点可核对的依据。

## 让记录跟着项目走

一项任务、一段投入和一笔收支都可以归到某个副业，之后从副业页或概览页查看它们的合计。记录的归属越一致，比较就越有用。比如同一笔支出若漏记，净收入会显得偏高；某段维护时间若没有补上，时薪也会显得偏高。数字不需要复杂，基础记录完整更重要。

八个页面分别照顾工作流程的不同部分：今天和本周帮助安排时间，任务和例行帮助管理要做的事，收支保存钱的记录，副业和概览用于查看项目情况，回顾整理一周的工作。你可以从眼前的问题进入相应页面，不必一次把所有信息都整理完。DeverDesk 把工作台搭好，怎么使用这些信息仍由你决定。
